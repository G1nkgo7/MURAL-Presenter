# Designer visual audit

Audit the rendered deck as one visual system against `memory/design-memory.md`. Do not judge factual correctness, narrative order, speech quality, or audience persuasion.

## System checks

- Palette and accent area follow the approved token system; no page introduces an unrelated color language.
- Title, body, number, label, and caption typography preserve their assigned roles.
- Fixed title/footer anchors, margins, spacing rhythm, corner language, and grid logic remain consistent.
- Similar page roles feel related without becoming copied templates.
- Adjacent pages vary composition and density intentionally; the deck has anchor, dense, and breathing moments.
- Photography, generated imagery, illustration, SVG, and charts follow the approved media division and treatment recipe.
- The signature motif recurs where promised and does not become decoration without meaning.
- Reference material has been translated into a case-specific system rather than copied as a recipe.

## Drift severity

Hard drift changes the visual system or makes multiple pages inconsistent: wrong tokens, conflicting type systems, mixed image treatment, broken global skeleton, or an unapproved second design language.

Soft drift is local craft that weakens the system without replacing it: inconsistent spacing, weak motif recurrence, one under-designed page, or an avoidable repeated composition.

## Routing

- Patch Designer-owned contract, tokens, art direction, or design memory only when the global system is wrong.
- Route a local layout or implementation defect to the affected Slide owner.
- Route exact copy, sequence, facts, or speech to Presenter.
- Treat element existence, broken paths, clipping, and page count as deterministic-code concerns.
- Default to targeted patches. Request broad re-authoring only when the frozen design contract itself fails.

Every finding must cite a `D-xx` constraint, affected slides, concrete rendered evidence, owner, and smallest valid patch.
