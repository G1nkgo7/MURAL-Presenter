# 方法简介

**MURAL-Presenter**（简称 MURAL；**Multi-Agent Unified Revision-Aware Authoring for Long-Horizon Presentations**）把演示文稿创作建模为一个具有外置、
持久状态的完整生命周期。

## 长程状态

这里的 horizon 不只是运行时长，而是事实、术语、叙事伏笔、视觉编码、受众假设或任务要求，
需要跨越阶段、页面与修改轮次持续有效的距离。因此，MURAL 主要回答三个问题：

1. 哪些决策必须属于整册？
2. 哪些关联页面需要一个共同负责者？
3. 哪些错误只有在整册汇合后才能发现？

## Shared deck blueprint

Orchestrator 解析受众、目的、语言、页数、证据需求、叙事结构、art direction、页面地图、
素材规划和完整 production groups。这些决策被持久化为 shared deck blueprint，再投影为精简的
group/page briefs，而不是在不断增长的对话历史中反复推断。

## 页面组

页面组是介于单页和整册之间的执行与责任单元。分组可以依据连续论证、首尾 bookends、章节过渡、
共享视觉家族、素材系列或显式跨页依赖。所有页面组完整且不重叠，不同组可以并行执行。

每个 Group Agent 负责本组全部页面：完成首稿、联合渲染、查看组联系表、合并缺陷、修改受影响页面，
并用最新像素完成复验。页面组共享的是设计 DNA 和叙事责任，而不是固定几何模板。

## 两级视觉闭环

组内检查可以关闭关联序列的连续性与节奏问题，但无法覆盖所有整册关系。因此，确定性装配后还会运行
whole-deck Review，检查事实口径、术语、setup/response、视觉语义、特殊页面与整体节奏。

## 修改路由

生成后的请求按影响范围分类：

- `local_revision`：不影响共享系统的定向单页修改；
- `group_revision`：一个页面组内部的关系或共同视觉语言变化；
- `evidence_revision`：需要新增事实或素材，并重做受影响页面组；
- `global_revision`：章节、标题链、共享系统、页数或多个页面组改变。

当影响范围无法可靠界定时，系统会升级到更高一级。目标不是不惜代价地减少工作量，而是避免一个
可以安全局部化的修改重新启动完整多智能体流程。

## 结构化 HTML 源

HTML/CSS/SVG 让文字、布局、媒体与图形保持独立可寻址，并以浏览器像素作为检查对象。
系统可以导出 PPTX、PDF 与图片，但不同适配层具有各自的保真度和可编辑性边界。
