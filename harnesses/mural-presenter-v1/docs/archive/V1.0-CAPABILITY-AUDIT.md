# MURAL Presenter v1.0 能力迁移审计

审计日期：2026-09-02  
迁移源：`harnesses/mural-presenter-v1.0`  
目标目录：`harnesses/mural-presenter-v1`  
文档性质：**v1 Alpha Vertical Slice 开工前的能力审计快照。**审计当时未达到 v1.0 生产能力等价，
也不能执行可信的 Skill-backed canary；当前进展与剩余 release 门禁见 `PHASE-6-SHADOW-REPORT.md`。

## 1. 审计口径

本审计同时对照三类事实：

1. 当前 `skills/mural-presenter-v1/SKILL.md` 的生命周期、角色和工具协议；
2. v1.0 的 557 项回归测试及生产入口；
3. 审计当时新 Harness 的实际代码、86 项局部测试和可执行入口。

“存在同名模块”或“旧测试仍通过”都不算已经迁移。只有新 Harness 自身能够通过同等行为测试，且
真实生成链路确实消费当前 Skill，才算能力已迁移。

本次复跑结果：

| Suite | 结果 | 能证明什么 |
| --- | --- | --- |
| 新 Harness | `86 passed in 6.49s` | 机械内核和现行 Skill 控制面协议的局部合同成立 |
| v1.0 | `557 passed in 78.08s` | 旧生产实现仍完整、可回滚 |

两套测试规模和入口不同，不能用“643 项共同通过”推导新 Harness 已覆盖 v1.0。

## 2. 审计时总体结论

审计时，新 Harness 已实现一组质量较好的**机械内核原语**：双 Provider transport、画布冻结、工具事务、
Owner Registry、条件事件、Artifact/hash 生命周期、基础 QC Ledger、Delivery 和 Training projection。

但当时生产生成路径仍缺失。`infer.py` 只能接收外部注入的 `generation_backend`；目录内没有正式
Orchestrator/Owner Agent loop、Skill loader、角色卡注入、创作工具实现、附件处理、Renderer 宿主、
环境预检或批处理监督器。因此目前的新 Harness 是可测试的 control-plane substrate，不是 v1.0 的
完整重构替代品。

## 4. 现行 Skill 协议对齐结果

本次已经消除四个会直接阻止当前 Skill 运行的控制面冲突：

1. `delegate_submit(tasks=[...])` 现在一次建立完整 wave，并在同一次 Owner Registry 文件事务中接受
   Material / Research / Image / Slide 合同；只让 `depends_on_image:true` 的任务等待唯一 Image task。
2. 等待与收集工具改为当前 Skill 使用的 `delegate_next_event` 和 `delegate_collect`，Schema 不暴露模型
   轮询 timeout。
3. Slide 的 `request_orchestrator` 与 Orchestrator 的 `respond_owner_request` 已形成同一 task、同一会话的
   暂停/恢复握手，并校验 `wave_id/request_id`。
4. Owner 角色只保留 `material/research/image/slide`；整册验收只允许 Orchestrator 调用
   `verification_submit(status="ready|issues_found")`，不再创建 Review Agent。

仍然阻止正式 Skill-backed 运行的不是工具名，而是生产实现缺失：

1. Skill 的角色卡依赖文件、搜索、抽取、图片和终端工具；新 Harness 尚未实现这些工具。
2. Skill 没有要求 Agent 手工调用 `artifact_commit`；新 Artifact 生命周期依赖显式事务，尚未把 Skill
   脚本产物、Owner runner 与该事务接起来。
3. 没有 Skill loader、角色卡注入和多轮 Agent loop，因此当前控制面没有真正的模型调用方。
4. `verification_submit` 的 Ledger 原语已有，但 finalize、联系表原生查看、独立 Critic、修复重启和同一
   issue 的复验闭合尚未连成生产循环。

审计时发现的旧画布文案已在本次同步修正：现在由 Orchestrator 首轮调用 `canvas_select`，Harness
只负责校验、冻结和传播；未指定格式也不再由 Harness 自动固定为 16:9。

## 5. 已删除的错误旁路

`runtime/host.py` 曾自行编写三段 prompt、私有 `page_author/visual_review_submit` 工具和固定单页 HTML
壳。它没有加载 Skill，也没有运行生产角色链。本次已删除该文件、对应 CLI 参数、测试和专用 fixture。

此前两条 27B 结果只能保留为历史 transport/kernel smoke，不能作为 Phase 6 canary、Skill 合规证据
或 release gate。
