# 页面构图参考

这些是起点，不是模板。Orchestrator 为整册确定一套视觉语言；Slide 再根据本页真实
证据和文案，把这套语言转成具体构图。

## 先判断表达任务

| 表达意图 | 可参考的页型家族 |
|---|---|
| 建立主题与承诺 | cover、image-hero、editorial-poster |
| 映射整册论证 | agenda、path、chapter-map |
| 让一个结论被记住 | statement、hero-metric、quote |
| 解释证据 | content、image-evidence、document-evidence |
| 比较选择 | comparison、matrix、matched-columns |
| 解释顺序或依赖 | process、timeline、roadmap、architecture |
| 回答定量问题 | data-chart、hero-metric、compact-table |
| 串起情境、行动与结果 | case-study |
| 把证据转成决策 | recommendation |
| 标记叙事转折 | section-divider |
| 留下最终观点或下一步 | closing |

页型家族描述的是沟通任务，不是完成后的组件树。不要因为卡片宫格容易实现，就让整册
反复复制同一种卡片。相邻页面应承担不同叙事职责，视觉变化应服务这些职责。

## 从页族到首稿构图

页族定“说什么”，`composition` 定首稿的主阅读路径：

| 页面任务 | 常用 composition | 主区域 / 辅助区域 |
|---|---|---|
| 真实场景、案例、文件或产品证据 | `visual-split` | 大图/证据对象 / 解释与结论 |
| 数据、地图、机制与关系 | `data-focus` | 大图表或机制图 / 少量注释 |
| 两个方案或状态 | `comparison` | 同尺度 A / 同尺度 B |
| 时间线、流程与路径 | `sequence` | 连续关系 / 结论或边界 |
| 清单、矩阵、精确查找 | `matrix` | 结构化主体 / 解释性结论 |
| 强观点、案例叙事或引句 | `editorial` | 主张/叙事 / 证据或视觉支点 |

不要只写“左图右文”或“三块卡片”。`构图蓝图` 应明确第一眼焦点、阅读顺序，以及
两个区域分别承载什么信息。骨架只是可改写的默认比例：Slide 可以翻转、重叠、拉宽
或压缩，但首稿必须保留一个真正占主导的视觉/证据事件。

请求很简短时，应从听众问题与证据推导页面职责，而不是反复排列 prompt 中有限的几个
名词。整册建立清楚的视觉节奏：强封面 Hero、身份重要时的真实场景或对象、关系重要
时的机制图或数据图，以及少量有意识的纯排版停顿。多样性来自论证，不是随机切换模板。

## 配色与视觉性格

先建立配色命题，不套行业刻板印象。说明颜色来自哪种真实线索，例如夜间光线、地方
颜料、自然地貌、产品材质、档案纸张、安全信号或时令物产，并分别定义画布、表面、
正文、强调、数据与特殊页的角色。只要可读性成立，内容画布可以是饱和色、染色、深色
或带材质的色场；不要反复把“专业”等同于白/米白配深蓝。

可参考的视觉方向包括：

- 高彩编辑：大色场、强裁切、超大字体、图文碰撞；
- 纪实田野笔记：真图、注释、地图、印章与克制但有彩度的标记；
- 触感印刷或拼贴：颜料、纸张、网点、切边与证据叠层；
- 发光技术：石墨或有彩深色、信号色、精确机制图，让光承担信息而不是装饰；
- 插画教学：友好形状、原创图解、温暖或活泼的色彩关系与清楚阅读顺序；
- 字体现代主义：果断网格、大字、非对称留白，以及承担结构的色块。

这些是词汇，不是预设模板或主题映射。选择一个主导性格，必要时搭配一个相容的辅助
性格；在系统内部变化裁切、尺度、密度、图解形式和表面处理。不要一册用遍所有方向，
也不要只为让相邻页面显得不同而更换配色。

## 封面

封面标题由 Orchestrator 定版，因为它定义整册承诺。确有必要时可加一行短副标题，
用来澄清受众、范围或观点。

看到真实标题和可用视觉证据后再选构图：

- 短标题可以居中，但要用有意义的图片、对象、SVG 动作、材质或字体关系形成视觉
  支点，避免只剩一片空画布；
- 中等长度标题适合图字分屏、下三分之一、编辑式或非对称构图，不要默认堆在顶部；
- 长标题按语义断句，用字号、字重或位置建立层级，并给足文字宽度；不要把长句一味
  放大到多行互相挤压。

封面通常需要一个主导 Hero。具名人物、地点、产品、作品、赛事或场地优先真实图；
概念表达可用生成图；抽象主题可用 SVG 或字体本身完成。只有当字体构图本身足够有
主张时，纯文字封面才成立。

辅助元信息要退居次级。封面不放醒目的物理页码、内部编号、来源行、KPI 墙或制作说明。

## 过渡页

先判断是否真的需要过渡页。过渡页是可选页型；只有整册存在至少 3 个需要明确停顿的
大章节时才考虑加入。每张过渡页应领起至少 2–3 张内容页；如果领不起，就把章节名并入
下一张内容页的 eyebrow 或章节标签，不单独成页。短 Deck（约 13 页及以下）默认使用
0–1 张过渡页，因为封面与结尾已经提供了首尾停顿。内容页必须始终是整册主体。

过渡页是停顿和下一章承诺，不是压缩后的内容页。通常只需要：

- 全册使用章节编号时的一枚数字；
- 一次章节标签或 eyebrow；
- 简洁章节标题；
- 一句过渡语；
- 一个语义母题或图片。

同一 Deck 的过渡页共享编号语法、字体角色、色彩逻辑、母题处理和空间气质，但不必
像素级完全相同。确有节奏价值时，可以在两种相关构图间交替，例如左重与图文分屏；
前提是仍明显属于同一系统。不同 Deck 则应根据主题和视觉契约形成不同系统。

`section_index` 只写短数字（如 `02`）。完整 `CHAPTER 02` 最多出现一次。不要在数字、
eyebrow、标题、母题和页脚里重复同一章节信息。

母题要有足够尺度承载转场。留白可以制造张力与焦点，但不能让所有文字和图像缩在
一个角落。过渡页不承载正文论点、KPI 矩阵或密集解释。

## 结尾页

除非用户明确不要，最后一页应一眼看出是结束。可以是一句凝练结论、感谢、Q&A 邀请
或真实的下一步。可以通过图片、颜色或母题与封面呼应，但画面中不能出现“呼应封面”
这类制作语言。

不要在结尾新增论点、虚构联系方式、密集行动矩阵或醒目的物理页码。建议或多项行动
方案放在前一张内容页；结尾只可重申一个已经建立的结论。来源留在讲稿。

## 普通内容页

普通页共享 deck 级 `--content-canvas`、标题节奏、安全区与页脚。Slide 可在这个系统
内自由变化图表、关系图、图片、拼贴纸、局部面板、强调方式和字体处理。

整页底色改变是一种叙事事件，不是单页随手调色。只有章节或峰值页确实需要时，才在
计划中声明有意义的 `canvas_variant`；否则保持画布连续，通过局部表面制造变化。

构图前可问：

- 听众离开本页时只需要理解哪一件事？
- 哪些证据让这个结论可信？
- 这个关系更适合通过图片、比较、顺序、数量还是文档来呈现？
- 主焦点在哪里，哪些内容可以删除或降级？
- 强调色是否有听众可见的语义理由？

数据页回答一个定量问题；对比页使用可比维度；流程页显示方向与依赖；人物/产品页
使用可识别主体和真正说明其相关性的事实；表格用于精确查找，如果听众只需看趋势，
优先图表或关系图。

所有可见文案服务听众。原始 URL、来源编号、证据代码、文件名、保密占位和设计说明
留在 `speech.md` 或 trace 中。
