# 图表与示意图

只阅读所分配页面需要的章节。图表或示意图必须回答页面标题；它不是装饰性插图。

## 通用规则

- 让视觉元素获得足够的版面权重，能够直接回答页面标题。
- 用 `--accent` 突出一个结论；上下文保持墨色或柔和色调。
- 把标签放在其所描述的标记附近。
- 使用真实的单位、时间范围和基线；来源引用写入 `speech.md`。
- 数据已知时，优先使用 ECharts 或 Canvas + HTML，而非截图；小型简单矢量标记才用 SVG。
- 在整套幻灯片中保持线条、圆角、箭头和节点的处理方式一致。
- 让视觉面成为整套幻灯片版式的色调组成部分。优先使用透明或从 token 派生的背景；
  不要在带底色或深色幻灯片内放置一个默认白色的图表矩形。
- 在页面规划中说明预期的视觉重心和支持轴。一个在技术上尺寸合规、
  却像小岛一样漂浮在大片死区中的图表并未完成。

## 选择图表形式

| 问题 | 推荐 |
|---|---|
| 哪一项更大或更小？ | 排序条形图或点图 |
| 某项指标如何变化？ | 折线图 |
| 聚类或异常值在哪里？ | 散点图 |
| 一个总量的构成如何？ | 少量部分用环形图；比较用堆叠条形图 |
| 从起始值到终值如何调和？ | 瀑布图 |
| 哪些维度相对强或弱？ | 使用共享刻度的雷达图 |
| 数量或资格在哪里收窄？ | 漏斗图 |
| 哪些输入收窄到一个关口，再展开为多个输出？ | 沙漏图 |
| 必须查到精确数值？ | 表格 |
| 按顺序发生什么？ | 流程或时间线 |
| 跨时间与工作流必须发生什么？ | 路线图泳道 |
| 哪些类别导致了某个观察到的问题？ | 根因 / 鱼骨图 |
| 什么依赖于什么？ | 流程或架构图 |
| 两个方案之间有何不同？ | 对照比较 |

如果受众无法说出该视觉回答的问题，则该形式尚未成熟。

## 条形与柱形

用于排序或离散比较。除非时序重要，否则排序展示。当条长编码大小时，
数量轴从零起。对重要条目直接标注；如标签使图例冗余则删除图例。

## 折线与面积

用于在连续轴上的变化。保留一条主导序列，以及完成比较所需的辅助序列。
标注拐点、峰值或决策点，而不是给每个样本贴标签。

## 散点

用于关系、聚类与异常值。说明每个轴的含义。强调支持论点的少量点，
弱化其余云团。

## 环形图、堆叠构成与瀑布图

对一个稳定总量中少量且可清晰辨认的部分使用环形图。将总量或页面结论放在中心，
对各分段直接标注，并将强调色留给关键分段。当需要跨周期或跨组比较构成时，
使用 100% 堆叠条形图。当带正负号的驱动因素将起始值调和到终值时，使用瀑布图。
不要在对齐条形图能更清晰比较时使用多个饼图。

## 雷达与象限

雷达图仅用于多个维度共享同一刻度、且各序列仍能清楚区分的情况。搭配少量直接读数，
让受众无需估算每个顶点。当决策取决于两个独立轴时使用散点图或象限图；
标注每个区域的含义，而不是仅仅画上十字准线。

## 表格

用于需要精确查阅的场景。数字右对齐，小数含义对齐，行分组，突出一个决策行或列。
若受众只需模式，则改为图表。

## 流程

选择一个阅读方向。当阶段重要性不同时，让其视觉上不等。简短说明放在节点旁。
仅在方向或依赖关系真实存在时使用箭头。

## 时间线与路线图

将耗时与工作流分开。标记当前点、决策关口或不确定性。不要把每个里程碑变成相同的卡片。

有意识地选择几何形式：

- 单轨用于时序；
- 平行泳道用于工作流或负责人；
- 阶梯用于能力成熟度；
- `now / next / later` 用于无虚假日期的方向性承诺。

改变里程碑的分量，仅连接真实依赖，并在每条泳道末尾为一个决策或结果留出空间。

## 架构

先展示层次、归属与数据流，再展示实现细节。空间上分组组件，标注边界，
连线交叉尽量少。大方框应表示真实的系统边界，而不是"用来填空间的东西"。

## 漏斗、循环与层级

只有当数量或资格在每个阶段收窄时才使用漏斗。只有当最后一个阶段实质性地回馈到第一个阶段时才使用循环。
只有当层级在权威、抽象或依赖上有所不同时才使用层级或金字塔。
不要因为这些形状轮廓看起来"具战略感"就选择它们。

对于漏斗，展示每个收窄步骤的数值与转化率；一串等宽的箭头是流程，不是漏斗。
对于循环，使用一组紧凑的节点、一个阅读方向和可见的回流边。保持标签水平。
中心结果可作为循环的锚点，但不能取代因果闭环。

沙漏图只用于真实的双向转化：多个输入收窄到一个决策、瓶颈、整合或模型，再展开为
多个输出。明确标注腰部关口，并让上下阶段具有因果对应；装饰性的蝴蝶结轮廓不算
证据。

## 根因与流程图

对一个观察到的效应使用根因图或鱼骨图，保留一组清晰可读的原因族及其简明原因。
让效应的标签最为醒目，并保持分支角度与间距规律。仅当数量确实在阶段之间流动时才使用桑基图或加权流图；
否则使用更简单的架构或流程图。

## 小型多图与混合图表

当同一指标需在多个组之间比较且不能出现折线重叠时，使用小型多图。仅在序列间存在真实的业务关系时才使用混合图表。
条形加折线的视图应说明两个轴，并在视觉上区分实际值、比率、估计值与预测值。

## 演示构图

- 让图表或示意图真正承担页面表达，不要把详细图表塞到卡片大小的角落。
- 使用结论式标题、清晰的图表舞台和紧凑的解读轴；只保留帮助受众理解结论的摘要数字。
- 在整套幻灯片中保持共同的图表外壳——图例样式、坐标轴处理和语义颜色——
  同时变化数据形式。
- 在一份长篇幻灯片中，变化的是信息机制，而非装饰性外框。
  排序条形图、路线图、雷达图、图片主导的分栏页和根因页可以共享同样的版式、字体、页脚和强调色。
- 在渲染后的 PNG 中，核查标记大小、标签大小、占据面积与平衡。
  在添加装饰性填充物之前，扩大或重构图表。

## SVG 制作

- 设置真实的 `viewBox`，让 SVG 随其容器缩放。
- 使用共享的 CSS 变量控制描边、填充与文本。
- 尽可能将标签保留为实时文本。
- 使用一种连线粗细和一个小箭头。
- 将强调色留给活动路径或结论。
- 避免曲线上文本、微小标签和连线交叉。
- 在渲染后的 PNG 中检查每个变量；无效的 CSS 变量会让重要标记悄然消失。

## 数据完整性

- 不要编造数值、精度、日期、来源或单位。
- 当条长编码大小时保留零基线；对任何有意截断的连续轴要加以说明。
- 区分观测值、估计值、预测值和情景。
- 当论点依赖来源时，在 `speech.md` 对应页记录引用；除非用户明确要求，
  不在页面上展示原始引用或 URL。
- 若数据不可得，改变构图，而不是展示虚假的占位符。
- 附件来源的 Figure 如果只有定性描述而无可恢复的精确数据点，禁止用 ECharts
  合成"看起来合理的形状"。此时应裁取原图（`bitmap-material`）或改用标注式
  定性示意，并在页面标注"示意，非原始数据"。

## markArea 正确语法

`markArea.data` 是端点对数组，每个区域由 **两个对象** 组成（起点和终点）：

```javascript
markArea: {
  data: [
    [{ xAxis: 'V1' }, { xAxis: 'V4' }],   // 正确：两端点对
    [{ yAxis: 10 },   { yAxis: 50 }],      // 正确：Y 轴区域
  ]
}
```

**错误写法**（不会渲染）：`{ xAxis: ['V1', 'V4'] }`、`{ xAxis: [0, 3] }`。

## 比较

在两侧使用相同的指标和基线。突出决定性的差异。
对齐的列、共享的轴或中间的权衡轴通常比两堆无关的卡片更清晰。

## 常见视觉失败

- 图表过小，从投影距离无法读清；
- 装饰性网格线强于数据；
- 无分类含义的彩虹色板；
- 未编码流向的箭头；
- 没有层级的方框；
- 无依据的精度或编造的数据；
- 一个洞见在同一页上同时以图表、要点和大数字重复呈现。

## ECharts 本地包

`assets/vendor/echarts.min.js` 已打包在 Skill 目录中。`prepare` 阶段会把它复制到工作区，
`_validate_fragment` 只允许这个精确本地 src。计划声明 `primary_visual_medium: echarts`
的页面在 HTML 中直接引用 workspace-root-relative 路径：

```html
<script src="assets/vendor/echarts.min.js"></script>
<div id="chart-NN" style="width:100%;height:480px"></div>
<script>
  var chart = echarts.init(document.getElementById('chart-NN'));
  chart.setOption({ /* ... */ });
</script>
```

不要引用 CDN、远程字体/数据/插件或使用 `fetch`/`import()`。使用 `--series-1…6` CSS
token 作为图表系列配色——通过 `getComputedStyle` 读取为**直接 hex 值**（ECharts 不能
解析 `var()`/`color-mix()`）。图表标签/图例不小于 20px；只有稀疏坐标轴刻度可降到 16–19px。
每页最多一个 ECharts 图表实例。`axisLabel:{hideOverlap:true}` +
`grid:{containLabel:true}` + `series[].labelLayout:{hideOverlap:true}` 是反重叠硬门。
`rich` 与 formatter 中的样式标识只使用字母、数字和下划线，例如
`{tag_open|OPEN}` + `rich.tag_open`；不要使用 `{tag-open|OPEN}`，ECharts 会把无法
识别的富文本 token 当成普通可见字符绘制到 Canvas。

Canvas + HTML 适用于 `canvas-diagram`，也是架构、机制、关系和流程的默认方案：
Canvas 画连线和背景几何，HTML absolute 层承载可读文本标签；同时覆盖动态布局、
高节点数、长标签文本或需要精确像素控制的关系图。
同样不依赖外部资源。

SVG 适用于 `svg-diagram`：节点少、标签短、锐利矢量几何确有价值的简单静态结构。
使用真实 `viewBox`，标签保留为实时文本，共享 CSS 变量。不要为省事把大型复杂结构
默认画成 SVG。三类载体都应承担清晰的信息职责，不缩成无意义角落装饰。
