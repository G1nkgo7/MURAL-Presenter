# 字体与排印

当演示文稿需要精心搭配的字体、富有表现力的展示字体，或更强的中西文层级时，请参考本文档。

## 角色模型

丰富的排印体系并非随意切换字体。为每个字体家族分配单一职责：

1. **展示（Display）** — 封面、分隔页、主张陈述，或一个决定性的数字。
2. **阅读（Reading）** — 页面标题、正文、表格、图表和说明文字。
3. **点缀（Accent）** — 引文、文化注释、手写批注或编辑提示。
4. **元信息（Metadata）** — 页码、日期、坐标和面向受众的紧凑标签。

大多数演示文稿只需要一组精简的字体家族。富有表现力的文化或编辑类演示文稿，
在每个家族角色稳定的前提下可以适当丰富。

## 显式激活各角色

字体词汇已在 `base.css` 中定义，但只有当 Orchestrator 为整份演示文稿分配角色后才会生效：

```css
:root {
  --font-display: var(--font-serif);
  --font-body: var(--font-sans);
}
```

不要仅因为它是安全默认值就保留 `--font-display: var(--font-sans)`。仅当中性无衬线
字体是设计意图的一部分时才继续使用，并在 `plan/deck.md` 的视觉契约中一次写明
展示、阅读、点缀和元信息角色。

排印首先服从于受众和场景，其次才是主题标签：

- 正式研究、政策、法律或机构类演示文稿：使用克制的字体组合；
- 富有表现力的文化、展览、教学或杂志类演示文稿：可使用更丰富但职责稳定的组合；
- 正文、表格、坐标轴和说明文字：始终使用阅读字体；
- 毛笔、草书、活泼或超粗字体：仅用于短暂的展示场合。

在长篇演示文稿中，优先通过变换尺度和构图带来变化，而不是新增字体家族。分隔页、引用页、图表页和证据页可以在共用同一套展示与阅读角色的前提下呈现出不同的观感。

## 可用字体家族

当前渲染环境中包含以下本地字体家族。`base.css` 中的每一个 CSS stack 都以 CJK 兼容的 fallback 结尾。

| Token | 主要家族 | 适用角色 |
|---|---|---|
| `--font-sans` | Noto Sans SC | 正文、图表、表格 |
| `--font-serif` | Noto Serif SC | 编辑类标题、引文 |
| `--font-grotesque` | Archivo, Manrope | 拉丁标题、指标 |
| `--font-display-serif` | Fraunces, Spectral | 杂志风主标 |
| `--font-kai` | LXGW WenKai | 人文、教育、平和的注释 |
| `--font-heavy` | Smiley Sans | 超大号中文主标 |
| `--font-brush` | Ma Shan Zheng | 文化类主标、大幅艺术短语 |
| `--font-hand` | 段宁硬笔楷书粗体 | 可读的手写笔记 |
| `--font-cursive` | 叶根友钢笔行书简体 | 仅用于大号表现性引文 |
| `--font-playful` | ZCOOL KuaiLe, Lovely Little Jelly | 青年、消费、活泼品牌 |
| `--font-mono` | IBM Plex Mono | 标识符、数字、元信息 |

将本 Skill 迁移至其他渲染器时，请先在目标环境中确认这些家族的可用性，再使用表现性 token。基于 Noto 的阅读栈始终是安全的 fallback。

## 搭配范式

### 研究或机构

- 展示：`--font-serif` 或 `--font-sans`；
- 阅读：`--font-sans`；
- 元信息：`--font-mono`；
- 可选点缀：`--font-kai`，使用一至两次。

### 技术或数据

- 展示：中文用 `--font-heavy`，拉丁用 `--font-grotesque`；
- 阅读：`--font-sans`；
- 数字与元信息：`--font-grotesque` 加 `--font-mono`。

技术感应通过尺度、对齐和注释体现——而非发光文字。

### 编辑或杂志

- 展示：`--font-display-serif`；
- 中文标题 fallback：`--font-serif`；
- 阅读：短段落用 `--font-sans` 或 `--font-serif`；
- 元信息：`--font-grotesque` 或 `--font-mono`。

### 文化或人文

- 主标题：`--font-serif`、`--font-kai`，或一个大号 `--font-brush` 短语；
- 阅读：`--font-sans`；
- 注释：`--font-hand`；
- 元信息：`--font-mono`。

### 青年或活泼品牌

- 展示：`--font-playful`；
- 阅读：`--font-sans`；
- 可选手写提示：`--font-hand`；
- 元信息：`--font-grotesque`。

不要在段落或数据标签中使用活泼展示字体。

## 让文字颜色匹配字体气质

字体选择与字体颜色是同一套系统：

- 类纸底色上的编辑衬线或楷体：使用碳黑、茄紫、林墨或其他有色深调；除非主题支持，否则避免默认的深藏青；
- 深色底上的粗黑无衬线：使用带轻微色调的高对比墨色，并把饱和颜料留给某一个词、数字或章节标记；
- 毛笔、手写与草书点缀：从主题图像或器物中提取一种颜料；不要把所有文化标题都渲染成通用金色；
- 图表、说明文字和表格：即便主标题富有表现力，也应保持阅读字体和稳定的墨色层级；
- 图像叠字：在检查实际裁切后，从整份演示文稿调色板的明侧或暗侧挑选文本色，而非套用统一的近白色标签配方。

展示角色的选择应源于主题的语气，而不是所谓“高级”字体的排行榜。产品目录、课堂、事故复盘、研究讲座和消费发布不应最终都归结为同一种衬线标题／无衬线正文的组合。

## CSS tokens 与类

将整份演示文稿的角色设置一次：

```css
:root {
  --font-display: var(--font-heavy);
  --font-body: var(--font-sans);
}
```

然后使用语义化类：

```html
<h1 class="type-hero">把复杂项目讲清楚</h1>
<p class="body-copy">一句支持主张的简短说明。</p>
<span class="type-mono">PROJECT REVIEW · 2026</span>
<strong class="metric type-grotesque">42%</strong>
```

`.type-brush` 或 `.type-display-serif` 等表现性工具类应作为局部例外。不要给每个元素都挂上不同的排印类。

使用 `base.css` 中共享的 `--fs-*` 字号变量；需要调整时对整份演示统一修改，不要
散落地设置一次性字号。

## 中文与双语处理

- 中文展示字的字距应接近零。适用于拉丁字体的负字距通常会让粗中文显得局促。
- 长中文标题应缩小字号，而不是强行套用固定的巨大字号。
- 标题使用 `text-wrap: balance`，短段正文使用 `text-wrap: pretty`。
- 人名、带单位的数字和短技术术语应通过 `.nowrap` 保持不换行。
- 双语标题应确立一种主语言。第二种语言应更小、更细或在空间上分离——而非等量重复。
- 仅在有对应字形的位置使用拉丁展示字体；CJK fallback 必须留在同一 stack 中。
- 表格、坐标轴和图例保持使用阅读字体。

## 展示字体安全规范

仅在毛笔、草书、活泼和超粗字体的轮廓本身构成信息的一部分时才使用它们。

- 毛笔或草书：通常 48px 或更大；
- 手写注释：简短且清晰可读；
- 超粗中文：使用宽裕的行高，不使用负字距；
- 装饰性拉丁衬线：核查标点、数字和 CJK fallback；
- 长段落：始终使用 `--font-sans` 或 `--font-serif`。

如果字体视觉上很突出但阅读困难，请缩小其角色，而不是添加描边、阴影或光晕。

## 视觉审阅

审视渲染后的 PNG，并自问：

1. 受众能否立即识别出标题、主张和证据？
2. 每个字体是否只承担一项稳定的职责？
3. 中文标题是否舒展而非被压缩？
4. 拉丁字体在字重和尺度上是否与中文自然共处？
5. 数据标签和说明文字在投影距离下是否可读？
6. 去掉某一个字体是否会让系统更清晰？如果是，就去掉。
7. 所选的展示角色是否真的出现在封面、分隔页或主页上，还是每一页都悄悄回退到中性无衬线？
8. 重复出现的页面类型是否使用了相同的字体角色、字号阶梯和标签字距？

## 排印密度地板

演示文稿的排印要兼顾密度与可读性。以下是绝对下限，不是目标值：

| 角色 | 最小安全值 | 说明 |
|---|---|---|
| 普通正文 | 24px | 投影距离基线；证据密集页可使用 24px，宽松页 26–28px |
| 图表标签/说明/来源 | 20px | 只有稀疏轴刻度可降到 16–19px；micro metadata 不能掩盖版面过满 |
| 内容页标题 | 48px | 与正文形成 ≥1.5× 落差 |

不要使用 `base.css` 未声明的合成字重（如 350、550、450）。可用的字重档位是
400/500/600/700/800/900；层级应由这些真实字重加上字号和颜色共同建立。当内容放不
下时，先缩减文案量或拆页，再尝试降字号；不能把正文降到地板以下作为布局"修复"。
这些档位表示整套字体资产的并集，不代表每个家族都具备全部字重；各家族的真实 face
以 `assets/fonts/manifest.json` 为准。尤其 `--font-heavy` / Smiley Sans 仅使用真实
400 face，在其上请求 500–900 会得到浏览器合成粗体，不能作为层级手段。
