# 图表与关系图索引

图表回答一个定量问题，关系图揭示顺序、归属或依赖；都必须直接支持本页标题。
先读下面的共用原则，再按问题进入一个专题。不要为显得丰富通读所有图种，也不按图种轮换凑页。

| 当前需要 | 读取 |
| --- | --- |
| 大小、变化、分布、构成、数值核对 | [数据图表](charts/data.md)中对应图种 |
| 流程、时间线、架构、因果、收窄与比较 | [关系图解](charts/relationships.md)中对应关系 |
| 准备写图或定位标签、图元、像素问题 | [构图与实现检查](charts/implementation.md) |

## 通用规则

- 让视觉元素获得足够的版面权重，能够直接回答页面标题。
- 用 `--accent` 突出一个结论；上下文保持墨色或柔和色调。
- 把标签放在其所描述的标记附近。
- 保留理解图表必需的单位、时间范围、口径和基线；来源定位写入本页证据，不默认上屏。
- 数据已知的常见统计图优先用已打包的 ECharts；需 SVG/HTML 定制时，由同一数据与坐标映射生成图元、刻度和标签，见[实现方法](charts/implementation.md#同一数据生成整张图)。用户要求原 Figure 时保留原图，不以重绘替代证据。
- 在整套幻灯片中保持线条、圆角、箭头和节点的处理方式一致。
- 让视觉面成为整套幻灯片版式的色调组成部分。优先使用透明或从 token 派生的背景；
  不要在带底色或深色幻灯片内放置一个默认白色的图表矩形。
- 在页面规划中说明预期的视觉重心和支持轴。一个在技术上尺寸合规、
  却像小岛一样漂浮在大片死区中的图表并未完成。
- 图表页用结论式标题、清楚的主图舞台和一条紧凑解释轨道组织阅读；只保留帮助受众抵达结论的辅助数字。
- 整册保持共同的图表外壳、图例方式、轴处理和语义色彩，同时按问题变化图形机制；变化的是信息关系，不是装饰边框。
- 渲染后核对图元尺寸、标签尺寸、占用面积和页面平衡。先放大或重组图表，不用装饰填补死区。

## 选择图表形式

| 问题 | 推荐 |
|---|---|
| 哪一项更大或更小？ | 排序条形图或点图 |
| 某项指标如何变化？ | 折线图 |
| 聚类或异常值在哪里？ | 散点图 |
| 一个总量的构成如何？ | 少量部分用环形图；比较用堆叠条形图 |
| 从起始值到终值如何调和？ | 瀑布图 |
| 哪些维度相对强或弱？ | 使用共享刻度的雷达图 |
| 数量或资格在哪里收窄？ | 漏斗图 |
| 哪些输入收窄到一个关口，再展开为多个输出？ | 沙漏图 |
| 必须查到精确数值？ | 表格 |
| 按顺序发生什么？ | 流程或时间线 |
| 跨时间与工作流必须发生什么？ | 路线图泳道 |
| 哪些类别导致了某个观察到的问题？ | 根因 / 鱼骨图 |
| 什么依赖于什么？ | 流程或架构图 |
| 两个方案之间有何不同？ | 对照比较 |

如果受众无法说出该视觉回答的问题，则该形式尚未成熟。

同一页可能需要两个互相支持的视图；它们应共享比较条件与编码，不能拼成互不关联的组件展览。
代码图形适合精确数据和简明关系，不将复杂产品、地景、人物和质感插画默认改成大型手写 SVG。
原 Figure 的真实性要求优先，素材裁切与保留范围见[素材参考](media/materials-and-images.md)。

常见失败包括：图表小到只能证明“有图”、网格线比数据更强、彩虹色没有分类含义、箭头不表示真实流向、方框没有层级、无来源精度过高、同一个结论同时写成大数字/图表/多条 bullet。
