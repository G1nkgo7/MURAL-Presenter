# 图形的构图与实现检查

准备制作或定位实际图形问题时读取。页型骨架和 CSS 边界见[HTML 契约](../runtime/html-contract.md)。

## 演示构图

- 让图表或示意图真正承担页面表达，不要把详细图表塞到卡片大小的角落。
- 使用结论式标题、清晰的图表舞台和紧凑的解读轴；只保留帮助受众理解结论的摘要数字。
- 在整套幻灯片中保持共同的图表外壳——图例样式、坐标轴处理和语义颜色；
  图种由问题决定，需要可比性时保留相同形式，不为求变化换图种。
- 在一份长篇幻灯片中，变化的是信息机制，而非装饰性外框。
  排序条形图、路线图、雷达图、图片主导的分栏页和根因页可以共享同样的版式、字体、页脚和强调色。
- 在渲染后的 PNG 中，核查标记大小、标签大小、占据面积与平衡。
  在添加装饰性填充物之前，扩大或重构图表。

## SVG 制作

- 设置真实的 `viewBox`，让 SVG 随其容器缩放。
- 使用共享的 CSS 变量控制描边、填充与文本。
- 尽可能将标签保留为实时文本。
- 连线粗细与箭头按关系保持一致；有不同语义时用可解释的差异编码。
- 将强调色留给活动路径或结论。
- 避免曲线上文本、微小标签和连线交叉。
- 在渲染后的 PNG 中检查每个变量；无效的 CSS 变量会让重要标记悄然消失。

## 数据完整性

- 不要编造数值、精度、日期、来源或单位。
- 当条长编码大小时保留零基线；对任何有意截断的连续轴要加以说明。
- 区分观测值、估计值、预测值和情景。
- 本页使用的数据与来源引用记录在分页计划的证据部分，不默认生成网站来源脚注或引用编号；
  上屏例外沿用 [Slide 角色卡](../../roles/slide.md)，不把“来源支撑论点”当成额外例外。
- 若数据不可得，改变构图，而不是展示虚假的占位符。

## 常见视觉失败

- 图表过小，从投影距离无法读清；
- 装饰性网格线强于数据；
- 无分类含义的彩虹色板；
- 未编码流向的箭头；
- 没有层级的方框；
- 无依据的精度或编造的数据；
- 图表、要点和大数字只是反复喊同一句话，没有各自的信息作用。

标题说出结论、图表提供依据、图签指出关键数值是合理配合；不要为“去重复”删掉受众理解或核对所需的内容。

## 同一数据生成整张图

常见统计图先用现有 ECharts，依赖路径见 [HTML 契约](../runtime/html-contract.md#图像图表与运行依赖)；
它处理坐标和刻度，但不会替你纠正输入数据、单位或模型假设。静态输出仍须显示完整图形与直接标签。
定制 SVG/HTML 时，将数据、绘图区与映射写在同一段本页代码中，生成曲线、点、参考线和刻度，
不要一边手填 path/polyline 的像素点，一边另写数值标签。

线性横轴用 `left + (value-min)/(max-min)*width`；纵轴用
`top + height - (value-min)/(max-min)*height`，只在映射处处理屏幕 y 向下。
标签可以独立避让，但被标注的点不能为排版离开真实位置；条图标签区不改变数据区比例尺。

供需、函数或阈值图先确定自洽的函数/数据，再计算交点和投影读数。
“曲线移动”的箭头连接同一条件下的两条曲线；“交点迁移”的箭头连接两个交点，两者不混用。
教学示例也须自洽；输入互相矛盾时交回确认，不能拉扯曲线去穿过几个独立猜出的点。
多页演示只改需要变化的参数，沿用未变曲线、坐标范围和颜色含义，别逐页重画参照系。

在已有的一次像素检查里，先核对方向、排序、比例与交点是否支持结论，再看标签避让和外观。
连续修改关系仍不对时，回到数据与映射整体修正；不靠增加折点或手挪刻度遮盖错误。
原 Figure 的单位、标签与完整边界受保护；发现裁切或不可读时回到素材与父容器定位，不能靠猜测重建证据。
