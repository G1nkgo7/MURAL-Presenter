# 页型索引

先按 deck.md 大纲与本页 brief 的表达任务选择对应参考，只读需要的小节。这里给作者制作方法，不由程序解析页型或选择骨架。
页型不是风格：沿用 deck.md 的视觉方向，不因换了一种表达关系就换整册字体、色彩与画布。

| 本页要完成什么 | 表达家族 | 读取 |
| --- | --- | --- |
| 建立主题与承诺 | cover / image-hero / editorial-poster | [封面](pages/special-pages.md#封面) |
| 映射论证、给出路径 | agenda / path / chapter-map | [大纲与阅读路径](pages/content-pages.md#大纲与阅读路径) |
| 让一个结论被记住 | statement / hero-metric / quote | [观点与关键数字](pages/content-pages.md#观点与关键数字) |
| 定位文句或记录中的问题 | document-evidence / teardown | [文档拆解](pages/content-pages.md#文档拆解) |
| 教会怎样填写或执行 | worked-example / template | [填写模板](pages/content-pages.md#填写模板) |
| 让听众现场判断或迁移 | exercise / practice | [课堂练习](pages/content-pages.md#课堂练习) |
| 从原图与细节中理解证据 | image-evidence / case-study | [证据图版](pages/content-pages.md#证据图版)；涉及素材时再读[素材参考](media/materials-and-images.md) |
| 比较选项，把证据转为判断或行动 | comparison / matrix / recommendation | [方案比较与建议](pages/content-pages.md#方案比较与建议) |
| 解释数量、时序或依赖 | data-chart / process / architecture | 按[图表索引](chart-index.md)选择对应方法 |
| 安排工作、资源与交接 | deployment / schedule / roadmap | [项目部署](pages/content-pages.md#项目部署) |
| 用已完成的工作证明相关能力 | track-record / case-study | [业绩与案例](pages/content-pages.md#业绩与案例) |
| 说明人物、经验与责任接口 | profile / team / organization | [人物与职责](pages/content-pages.md#人物与职责) |
| 标记叙事转折 | section-divider | [过渡页](pages/special-pages.md#过渡页) |
| 收束观点或留下下一步 | closing | [结尾页](pages/special-pages.md#结尾页) |
| 比较多页或整册关系 | contact-sheet review | [整册自检](pages/review.md) |

这些词帮助模型理解任务，不规定卡片数量、像素坐标、页面配额或固定模板。
只因“宫格好实现”而让整册反复复制组件树，会抹掉比较、解释、转折与收束的区别。
用户给定页数与页段优先，不为凑齐本索引而补封面、目录或过渡页。
