# 整册与分页 Markdown 规划

规划既是制作输入，也是供人理解、审阅和持续修订的工作稿。整册方案、研究正文与本页依据各有职责，
内容具体到可以使用，不以字段齐全代替解释完整。路径沿用当前工作区，不建立另一份可编辑 JSON 页表。
deck.md 保留分页大纲；完整分页正文只在独立 brief。章节可以叫 Pages 或“大纲”，程序不把共享文稿中的章节解析为第二套分页计划。

## 文件职责

| 文件 | 作者与职责 |
| --- | --- |
| `config.json` | Orchestrator 可写、专家只读：当前工作语言、呈现语言、目标页数；有独立讲述要求时才指定讲稿语言 |
| `deck.md` | Orchestrator：受众、目标、讲述主线、可审阅的分页大纲、具体整体视觉规范表；不另建 design.md |
| `base.css` | Orchestrator：最小运行底座与本册共享设计的实际 CSS；单页构图不在此累积 |
| `briefs/slide_NN.md` | Orchestrator 协调的本页制作依据：讲清什么、相关证据、真正显示什么、图像/图表的解释作用、讲稿与必要约束；不写死全部构图 |
| `research/*.md` | 各 Research 只写委派回执分配的任务稿：完整解释、依据、来源定位与不确定性；续做沿用原路径 |
| `knowledge.md` | Orchestrator 维护本册已采用的解释与依据，保留必要推理、条件、原件定位和相关任务稿链接，并处理结论冲突；不复制全部研究稿 |
| `assets/catalog.md` | 素材作者通过已有脚本显式登记的可读投影：真实路径、消费者、用途、来源、许可/署名要求、裁切与不可得原因；不手写回灌机器状态 |
| `speech.md` | 按最终页面整理的连贯讲稿：解释、观察顺序、衔接与必要补充；结束或导出时从当前分页讲稿提取，不独立维护 |

这些是职责边界，不是每次都要填满的栏目；有实际研究或素材工作才生成对应文档，不为目录齐全创建空文件。
分页计划的证据部分引用本页相关的页码、URL 和论据，不复制完整 knowledge.md 或素材登记。
屏显内容只列真正需要显示的内容；用户点名的内容、指定页位、原文和页内引用必须进入对应 brief 的现有内容与证据部分。内部制作定位与真实文献引用分别处理，引用按 [Slide 角色卡](../../roles/slide.md#保持证据真实画面可读) 保留，不以屏显减负隐藏硬要求。
HTML 是实际屏显产物，不是第二份计划；brief 是意图与边界，不要求它逐字复述全部 HTML。
Research 修正后，Orchestrator 将采用的结论、原件定位和限定写回相关 brief，再委派或续做。goal 只说明本次工作与保留项，不维护另一份当前文案；局部排版修复不要求重写无关计划。
自然章节按工作语言命名并按需组织；其中准备上屏的标题、文案使用呈现语言。讲稿章节的明确提取边界见下文，其余章节名称不作为控制参数。

## config.json：当前创作设置

```json
{
  "working_language": "zh",
  "presentation_language": "en",
  "target_page_count": 10
}
```

这三个字段始终存在。未确定的语言可在启动时为 null，由 Orchestrator 理解 Query 后、开始相应制作前补齐；
用户明确要求优先，不用 Query 字符比例锁定语言。工作语言用于研究、协作和制作依据，不保证模型内部思考语言。
呈现语言用于受众看到的文字：即使 brief 说明是中文，其中准备上屏的标题、正文与图注仍可为英文。
讲稿默认随呈现语言；只有用户另有讲述语言要求时，才增加可选 `speech_language`，不在每份文稿重复声明。

`target_page_count` 是正整数或 null，表示目标而非已完成页数；实际页序和数量由页面文件及已有索引反映。
Orchestrator 使用现有 write_file/patch 修改配置，专家只读。明确入口参数仅初始化一次，后续消费当前 config.json；创作配置只包含上述设置，不混入部署、调度或审计信息。
色值、字体、画布和共享样式不在这里重复配置：设计理由写 deck.md，实际实现写 base.css。

用户要求改变时再修改对应配置，不为过验收降低要求。改工作语言影响后续协作，不重做无关页面；
改呈现语言后由原责任方修改并复核相关页面、讲稿；改目标页数不自动创建或删除页面，实际结构仍通过现有修订流程调整。

## deck.md：整册为什么这样讲、这样画

```markdown
# 面向听众的整册标题
## 任务说明
受众起点、使用方式、讲者/读者、时长、要解决的问题与期望的理解或行动。
用户硬要求与事实/视觉来源边界；仅对缺失项作有依据的选择。
## 大纲
先说清主线与论证递进，再用短表或列表给出分页大纲：页号、工作标题、封面/展开/转场/收束等叙事角色、本页的核心推进、主要视觉事件及对应 brief 链接。
## 视觉故事板
按页或连续页段说明第一眼应看到什么、视觉证据或关系如何推进叙事、哪些页是视觉峰值或停顿。每页至少有一个可执行的主导事件：真实图像、机制图、数据主图、路径/流程、文档证据、对照关系、强排版停顿或练习对象。不要让整册退化为连续的均质卡片页。
## 整体设计规范
先说明属于本主题的视觉命题、调色来源、视觉性格和反默认选择，再用规范表列出本册实际采用的颜色、字体、排印、图像处理与共享规则，以及各自用途和适用范围。
封面/过渡/结尾使用怎样的同源系统；哪些惯常处理不适合本册，以及为什么。
```

分页大纲覆盖全部计划页，便于审阅篇幅与推进；简明摘要和 brief 链接不是重复计划，不抄完整证据、讲稿或执行状态。deck.md 到叙事骨架、设计合同和每页表达重心为止，不列局部框、块、胶囊、组件数量或坐标清单；具体构图留给页面作者根据真实素材和截图完成。首次制作页面或提交 Image/Slide 前，按[设计校准](../design-calibration.md)把一次紧凑合同写进视觉故事板与整体设计规范；它不是新增字段或审批。

视觉故事板说明封面如何抓住主题、内容峰值由什么证据承重、过渡怎样换挡、结尾如何收束。每页写清主导视觉事件和第一眼焦点；没有明确观看对象的内容页应回到受众问题重新规划，而不是平均拆成三四个文本块。
标题链要能独立读出推进，不只是“背景、现状、问题、方案”这类容器标签。
内容页标题表达证据支持的发现或行动，例如把“行动项管理”改为“把‘尽快处理’改成可追踪的行动”，
并用对应实例兑现；不为标题有力而扩大断言。必要条件留在相邻副标题或图注，封面、转场和练习不强制写结论句。
把每页新增的理解或行动说清：同一个对象可以从观察、拆解推进到应用，不把定义、换词复述和总结各占一页。
用户给定页数与页序不变时，调整各页证据与任务，而不是补装饰或擅自删页；必要回顾要说明它现在帮助什么判断。
视觉规范只写本册采用的真实决定：题材线索、语义色值、字体职责、网格、结构家族、图像处理、节奏和反默认选择。用户的风格词必须进入构图轮廓、媒介/裁切、展示排印、留白与密度；只换主题色不算设计方向。共同网格、图例、页脚或母题只定义一次并落实到 base.css，brief 只写本页例外。共享语义不等于所有页面同一几何；只有连续比较、同一底图逐层展开或共同坐标本身承担理解时，才锁定对应几何。
共享组件服务受众的阅读与导航，不把页角色、制作意图或制作序号变成每页必现文案。
字号与密度依据真实画布、阅读距离和使用时长设定，不从示例抄一个通用配额。
屏显内容要做取舍，不把全部证据与讲稿列为必显。需要真实话术或文献实例时，选能暴露关键机制的短节选，原文全文与定位留在证据部分；节选保留条件与否定，译文或释义不冒充逐字原话。用户要求全文展示时尊重要求并调整承载。
封面/开场页默认承担建立主题、情境和观看动机，不承担解释、证明、列数据、拆机制或总结要点。用户明确要求的开场内容、原文和页位优先，不能以本默认规则删掉。
如果用户给出的开场场景中包含表格、图像、事实、机制、条件对比等信息，除明确要求本页展示的内容外，只选择最能制造问题感的元素上屏；其余非必需展开进入后续页面、讲者备注或后续讲解，不要全部塞进封面。
封面优先建立主题与观看动机，详细论证和目录按需要安排在后续既定页段；不靠压缩字号解决规划过载，除用户明确要求外，不把表格、完整图表、多段解释或三条以上事实说明列为封面必做项。
封面 brief 写清主题图像、对象或关系示意的第一眼焦点及其表达意图，不只列标题与问题句，也不把“关键词＋彩色色块”命名为关系 Hero 就视为完成。示意说明可辨认的主题对象或结构，以及要看见的真实关系；具体构图留给作者。用户指定的数据开场保留数字、单位、口径与页位，并说明如何让有依据的对比或变化可见，不把放大的文字数据带当成关系表达。纯文字仅在用户明确要求文字主导或文字本身是展示对象时采用；其他情况下优先现有材料或简明准确的主题示意，不为补图突破来源限制，也不因构图偏好自行禁用原本允许的素材。
约束锁定用户要求、事实与共享语义；局部字号、位置、图文比例和组件数量通常留给页面作者据实际可读性调整，别把设想的构图升成不可调整的合同，也不以微小图注迁就过载计划。
例如写“连线把资源交接点与对应收益连接，端点可辨、标签不被穿过”，而不是先规定“从左边界画 900px 虚线”。用户明确要求的尺寸、同一数据坐标和有证据的局部修复定位仍保留；这不是禁止作者使用精确几何。
未看到实际素材前，方向、比例和可裁范围保持待确认，不把构图假设写成必须保留的条件。证据需供观众比较时，先保证图与必要标签可读，再安排排印强调。
留白用于聚焦、分组或阅读停顿，不要求每页留一条空带。具体排印与局部构图可经页面反馈调整；共享决定变化时由 Orchestrator 同步规范与实现。

使用方式决定哪些支持必须可见，风格决定如何呈现；不增加模式字段或自动路由。例如：

| 使用方式 | 页面应保留的理解或判断基础 |
| --- | --- |
| 投影微课 | 当前观察对象、关键关系与需要学生判断的问题；延伸讲解放讲稿，不删掉推理中间依据 |
| 自学/发送阅读 | 可独立理解的定义、条件、示例和必要解释，不能把答案所需信息都藏在讲稿 |
| 决策汇报 | 可比较的选项、证据、口径与权衡，清楚区分建议、已知事实和待确认事项 |
| 研究展示 | 问题—方法—证据的对应，图表的变量、口径和适用边界；现场与阅读版按实际用途取舍 |

这些是取舍示例，不是每册必须覆盖的栏目。证据稀少但充分的页可聚焦放大，证据缺失的页应先补证据或收窄主张。
大标题说明主张，可操作的实例/图表让它成立；不要以“极简、峰值、停顿”为由把实例挤成脚注。
材料转换中的派生数据在证据部分写清原值与可复算关系；概念示意不伪装成测量值。原件一基页码、Figure 编号和引用文案保存在证据部分；普通任务不自动上屏来源，用户或任务启用引用时沿用核准定位，不用本演示页码或抽取块序号替代。按 Slide 引用规则保留必要署名与事实边界，内部路径不冒充引用。
为教学补写的实例或建议模板注明性质，不把它称为用户已实施的内部标准，也不为增强冲击补无来源统计。

主题变量、字体角色、画布宽高及真正跨页复用的 `.deck-*` 样式直接写在现有 base.css；保留公共画布、播放器和结构原语，单页构图写入所属 HTML。
deck.md 不嵌入用于执行的 CSS，程序不从规范表或散文生成样式，也不按文稿中的路线名称覆盖字体。
选字体时可参考 [字体与排印](../typography/fonts-and-type.md) 的目录，选择结果由 Orchestrator 落实到真实 CSS。

## knowledge.md：按问题理解材料

研究任务稿保存查到了什么，knowledge.md 整合本册采用什么。Research 完成后由 Orchestrator 读取 `research/*.md`，筛选本册真正采用的结论，处理冲突、口径和不能推出的边界，再写入或修订 `knowledge.md`；Slide 和 brief 以后者作为统一事实底稿。正文可参考下面的组成，按实际问题选择段落、表格与章节，不把示例变成必填结构或重复的 claim/source/boundary 标签：

```markdown
# 研究主题
## 研究范围
这次要回答什么，使用哪些材料，哪些核心前提已确认。
## 具体问题的答案
用实际问题作小节标题，连贯解释事实、原因、数据与必要推理；引用紧邻所支持的论述。
## 图表与素材线索
有实际候选才写：它表达什么、原件定位或真实路径、必须保留的部分，以及尚未核实的限制。
## 限制与未解决问题
只列会影响本次理解或制作的缺口、冲突与适用条件。
## 来源
用链接、脚注或简短列表列明实际使用的材料及定位，能对应正文；不罗列全部搜索结果。
```

正文中可多次引用同一来源，来源清单集中写完整定位，不复制研究正文。没有候选或独立缺口时省略相应章节。
研究解释和来源定位留在同一文件；不把“来源”另拆成文件，也不因为有来源表就省略正文中的证据对应。
从研究稿整合到 knowledge.md 与 brief 时，沿用已核验的原件页码、图号和数字口径；凝练不能改变否定、条件、对象、时态、完成状态或确定程度，也不能把“计划、筹备、预计”变成既成事实。用户补充设定与附件记载分别说明，核心冲突不静默裁决。
任务回执简述结论、缺口和实际路径，不复制完整正文。Orchestrator 采纳时保留必要解释和计算依据；采用的证据已同步 `knowledge.md` 与相关 brief 后，该页即可制作，不等所有研究稿全部写完。

## briefs/slide_NN.md：本页怎样让论证成立

```markdown
# 六次测量，让一条关系显形
## 本页任务
学生从同一控制条件下的数据判断关系，而不只记公式；本页先观察，下一页再解释斜率。说明本页是封面、内容展开、转场、练习还是收束，以及它在标题链中新增什么理解。
## 页面内容与证据
只写本页必须显示的文案、原文或数据，以及影响理解的单位、条件与示例性质；延伸解释留讲稿，完整研究沿知识章节引用。
本页相关研究引用到 knowledge.md 的具体章节及已核验的原件页码、Figure 编号或链接，不抄入整份研究。用户点名的内容、页位、页内引用和指定原文写明并保留；改写沿用条件、时态、完成状态和确定程度，不能把计划或筹备改成完成。
## 视觉表达与约束
同一坐标下呈现散点与拟合线，让学生看到关系而非先背公式；对应解读贴近数据。
写清主导视觉事件、第一眼焦点、阅读顺序与事实边界；构图起点作为建议，不枚举组件数量和局部位置。需要观察的证据承担画面主体，文字说明它支持什么。
有图片时给真实素材引用及必须保留的主体；只写本页特有的约束，留给页面作者决定实际构图。
## 讲稿
先请学生描述点的关系，再解释拟合；说明“示例数据”的性质和适用条件。

留一个真正需要听众回答的问题，不照着屏幕逐字朗读。讲述中依次引导：
- 先观察各点随横轴变化的总体方向。
- 再比较个别测量偏离，区分趋势与单次误差。
```

这是内容组成示例，不是要照抄的教学主题。正文原文进入所属 Owner 的输入；技术元数据不能代替正文，也不需要再把正文各抄成一个 key/value。
本页任务承接大纲里的叙事角色；视觉表达描述对象、阅读顺序和必要关系，不指定某种 DOM 外壳。封面、过渡、结尾作者先读对应方法，其他表达按需选读。brief 区分用户硬要求、必需屏显证据和可调整的构图建议；作者可凝练非指定原文、重分比例、裁切与局部布局，不改变事实或隐藏必要条件。若多个解释块、表格和完整图表争同一焦点，先减去复述与延伸解释；封面和转场优先减负，内容页突出最能证明结论的视觉事件，不把过载清单交给作者靠缩字兜底。
P1 或明确开场页的 brief 默认写成开场钩子，而不是内容页清单：保留标题、简短副标题或问题句，以及一个主视觉或情境线索。用户明确要求的开场内容仍写入本页，不擅自推后或藏入讲稿；其他细节不要求表格、机制拆解、多条事实说明或完整图表同时上屏，放入后续页、讲者备注或后续讲解。
内容与证据较长时可分小节或表格，明确屏显与后台依据的边界。只有一段能说清时不再拆空栏目；讲稿仍保留明确章节边界。
“突出技术优势”不足以制作：要交代具体技术、解决的问题、依据和要让听众看懂的关系；材料不足就指出缺口，不以套话填满。
证据保留本页可直接使用的数据、条件和相关来源定位，长篇研究沿 knowledge.md 的章节引用，不复制整个研究文件。
讲稿直接写在唯一的 `## 讲稿` 或 `## Speaker notes` 章节中，支持正常段落、列表和下级小节；到下一个同级或更高级标题结束，不读代码块内的伪标题。
它是讲稿真源，不必因为还没导出就省略讲述设计。Harness 在自然收尾和导出时派生 `speech.md`，不把普通正文猜成讲稿；模型无需另行触发同步。
没有讲稿可以明确省略，部分缺失应如实交接；页面标题数不等于有效讲稿数。

### 仍由程序读取的最小协议

页号由 `briefs/slide_NN.md` 的文件名取得，最终页序连续；制作中可先准备、提交已就绪页，不要求其余 brief 同时完成。正文以一个普通一级标题开始，不重复要求标题携带技术页号。
页型在大纲与本页任务中用自然语言说明，不写 `page_type` 字段。程序不从标题、正文或页号推断类型，也不按类型选择骨架；封面、内容、转场和结尾使用同一运行容器，差异由作者实现。
讲稿仅按上述明确章节提取；其余任务、证据、媒介、构图与页脚意图写自然正文，不再重复成机器摘要或枚举。
比较、流程、案例、方法、文献证据、核心指标是表达词汇，不是枚举或模板指令，也不以字段齐全判断好设计。
语言和目标页数只在 config.json；实际页数与文件对应关系沿用已有索引，移动、插入、删除由当前修订命令处理。

## 工具派生文件与实际产物

`assets/catalog.md` 按素材展示实际文件、来源与许可、消费者、主体、裁切及限制；继续由登记工具投影。
它的机器字段或标题不是文稿写法模板，不手改目录排版或另抄一份素材状态；具体登记参数见素材参考。

`speech.md` 由工具按页生成标题与连贯讲稿；各页解释、观察顺序和衔接先在对应 brief 中写好，再在结束或导出时提取。
它不是只把屏幕文字拼起来，也不需要再次按 claim、action 等字段拆散讲话。

`base.css` 使用真正的 CSS：画布与基础重置、本册字体/色彩/排印、实际复用的组件及必要播放器规则；单页构图留在所属 HTML。
`slides/slide_NN.html` 是页面实现，`present.html`、PNG、联系表及导出文件是实际或派生产物，不额外配写一套重复文稿。Harness 的运行记录不是作者文稿，不把制作状态复制进上述正文。

## 从页面反馈到计划，再到讲稿

规划并非一次性锁死。页面制作可能发现正文放不下、图不能正确裁切、图中关系与叙事不一致，
或讲稿重复/漏掉必要条件。委派页带当前证据与建议交回 Orchestrator，自制页由主 Agent 直接同步相关计划，不另写交接副本。

- 局部措辞、布局、裁切在既定论点和边界内，由原页面作者直接完成。
- 新证据改变结论时，Research 更新自己的任务稿并交回受影响主张；Orchestrator 同步采用后的 knowledge.md 和相关计划，不并发覆盖任务稿，也不让失效结论继续作为当前答案。
- 影响标题链、事实边界、必需内容或其他页时，Orchestrator 明确所有受影响页，修改相关 brief、deck.md 大纲或共享规范，再交回原 Owner；只更新受影响部分。
  多页共用同一事实时一起修正，不依赖程序从文稿关键词猜关系；已显式登记的素材消费者和依赖仍沿用原记录。
- 已有正确证据和素材复用，不以一次计划修改为理由重新搜索、生成或制作全册。
- 讲稿根据最终屏显关系调整：解释必要边界、指出观察顺序、安排停顿与承接，而不是复制屏幕文字。
  页面删除或修正的断言，也核对讲稿章节；“左边、中央、右侧”等指称以最终图中位置为准。
  讲稿中的事实与屏显使用相同证据标准，不能把无依据的数值或错误解释移到讲稿规避核验。

结束或 export 时统一从最新分页计划提取 speech.md。后续修改仍回到 brief 的讲稿章节，
再提取覆盖派生讲稿；不尝试自动将任意 HTML 或 speech.md 反向同步成另一份计划。
所谓双向优化是有判断的内容协作，不是文件镜像或自动覆盖。
