# 页面制作

把负责页面的任务与证据做成内容完整、适合真实使用场景的画面。整册计划确定主线、事实边界和共享设计；你负责具体措辞、构图、尺度、素材编排、实现与看图修复。本方法也适用于 Orchestrator 自制页。

## 输入足够就开工

以原始 Query 和明确修改为最高要求，先消费交接中的整册设计方向与所属 brief，再按需读取相关知识、已交接素材、当前 HTML 和 `base.css`，不重复加载已经完整收到的文稿。保留事实与必需屏显内容；其余解释可凝练或留给讲稿，不能藏掉独立理解所需的条件。局部构图建议妨碍承载或可读性时可以调整，真正需要改变论点、页职责或共享设计时交回 Orchestrator。

沿用整册色彩、字体、图像处理和稳定锚点，不重选风格。协作与交接使用 `working_language`，屏显文字使用 `presentation_language`，讲稿默认随呈现语言；原文、专名和代码保留必要原貌。

## 首稿设计起点

先把本页的题材线索变成一个可见选择：标题的字形与断句、主体的尺度与裁切、证据的组织或留白方向，而不只换颜色。让标题、主体和辅助说明有明显的大小与空间主次；图片围绕真实对象安排，文字沿静区或共同轴线进入画面，不先摆好等权容器再塞内容。

展示与阅读声部可以同家族，但要有清楚层级并符合题材语气。中文展示字看实际汉字轮廓，不把拉丁家族名加正文 fallback 当作已完成选型；需要诊断时只读[字体与排印](../references/typography/fonts-and-type.md)的相关小节。

首稿前按本页任务选择构图：放大一份关键证据、让可比对象共享尺度，或让关系主图统领标签与说明。具体比例从阅读条件与真实素材出发，正向示范见[内容页构图起点](../references/pages/content-pages.md#首稿构图起点)。不另写设计分析文件，也不把选结构变成新的审批步骤。

## 先决定观众看什么

每页先确定一个主导视觉事件和清楚阅读顺序：观众第一眼看什么，接着比较、追踪或判断什么，辅助文字怎样帮助完成它。优先把时间投入最能让本页被记住的对象，让图片、图表、机制、文档证据、题干、比较关系、路径或强排印焦点中的至少一个承担画面主体，通常占 40%–70% 的有效阅读空间；不要把制作时间平均分给同权小部件。

- 比较：共享尺度、条件和基线，让真正影响判断的差异醒目。
- 过程或机制：让方向、变化和依赖可见，标签贴近对应对象。
- 数据：用图形表达关系，保留单位、口径与限定；只看趋势时不默认堆完整数表。
- 实例、练习或文档：放大观众要读、修改或判断的原句、题干和数据。
- 案例或图像证据：让真实对象与关键细节承担主体，说明它支持什么、不能证明什么。

可从 `base.css` 的五个可组合原语起步：`hero` 适合一个主视觉加简短钩子，`focus` 适合标题锚点加大尺度证据，`split` 适合主次明确的图文并置，`compare` 适合共同尺度下的对照，`sequence` 适合步骤、时间或因果推进。它们不是页型模板；按内容调整比例和内部结构，也可以不用，但不要重新发明安全区和基础间距。具体 HTML 见 [HTML 合同](../references/runtime/html-contract.md#可组合的结构原语)。

封面、过渡、结尾开工前先读[特殊页方法](../references/pages/special-pages.md)的对应小节；已在当前上下文中读过的方法不重复读取，不通读整套参考。封面建立观看动机，过渡制造停顿，结尾只保留一个收束动作；不要把三者都做成缩短的内容页。其他表达按[页型索引](../references/page-index.md)选读。

## 保持证据真实、画面可读

画面只放帮助理解、比较或行动的信息。内部制作角色、状态、缓存路径和任务编号不上屏；真实文献引用、附件页码、Figure 编号和必要署名不是内部元数据。普通任务默认把来源定位留在研究稿与 brief 证据中，不自动为每页、每图添加引用脚注或来源页；只有用户或本次任务明确要求引用时才按要求上屏，素材许可必需的可见署名始终保留。启用引用时，简短出处紧邻其支持的内容，不因极简或封面减负删掉。

引用沿用已核验的原始附件一基页码、原文 Figure 编号或真实链接，不用本演示页码、抽取块序号或记忆猜定位。未核准的来源交接为缺口，不编造页码、图号或出处。单位、时间、口径以及“示意、估算、目标、假设”等事实限定仍靠近相应主张；凝练不得改变否定、条件、对象、时态、完成状态或确定程度。数据标签、表格、表达式与图形从同一依据生成，不能各自改写出矛盾。

使用已交接素材的真实路径，检查它进入页面后的主体尺度、裁切、静区和图字关系。素材下载、登记与生成新裁图由 Image 或 Orchestrator 处理；阅读素材参考不赋予执行 `image.py` 的权限。你可调整本页 CSS 的显示范围，需改变素材文件时交回素材作者。没有可靠静区就改为并置或请求换图，不能用蒙版遮住证据换取清楚。原 Figure 保留必要轴、单位和标签；连续比较沿用同一底图、坐标和图幅。

内容过载时先删除无增量复述、放大有效主体并协调页间承载，不靠缩小重要文字。卡片只在分组关系确实需要边界时使用；不要把四个同权卡片、每页同一标题栏或装饰性图标当默认构图。默认让页面边缘安静，不用装饰性小字、状态标签、胶囊、常驻信息栏或无叙事作用的页眉填满空白；必要页码、来源、图例和标注保持简洁并直接服务内容。

## 做成可评价首稿，再集中修复

先完成真实文案、主体视觉和局部 CSS，形成可评价首稿后再用 `inspect` 渲染并查看当前像素；不要为每个小块单独预览。已有页面优先局部修改，单页 CSS 作用域限定到当前 `#slide-NN`，共享样式变更交给 Orchestrator。写入、DOM、资源和像素未变的诊断见 [HTML 合同](../references/runtime/html-contract.md) 与 [执行参考](../references/runtime/commands.md#写入与像素未变的诊断)。

用当前 PNG 一次找齐影响使用的问题，按位置、后果和修复目标合并处理。首稿后的修改只服务真实缺陷：事实或图形关系错误、素材未出现、裁切/遮挡/溢出/贴边、小字、主体太弱、用户指定情境被替换，或视觉合同只写在计划里而没有进入画面。可读、正确且已满足明确视觉要求后收口，不为轻微偏好换构图或重做风格。

## 检查语义

`inspect(page=[页码], ...)` 的 question 写用途和关注点，不预设通过；局部修改也要复核整页基础版式。

| 阶段 | 用途 |
| --- | --- |
| `draft` | 草稿或占位自检，只判断骨架、可渲染性和基础版式 |
| `final` | 内容与关键素材稳定后的单页终稿验收 |
| `blocking_recheck` | 阻塞问题修复后的定向复检 |

一次检查覆盖四边安全区、底部余量、裁切/遮挡、主体尺度、图文分量、文字和图例可读性，以及数量、单位、标签和连线对应关系。按真实展示比例判断；需要放大才能辨认不等于投影可读。外部 Critic 的意见须对照像素和任务判断，失败或不完整不能冒充“无问题”，同版本有效检查也不重复获取赞同。

Group 还需通过联系表检查共同坐标、图例、色彩角色、排印和节奏；有疑点才放大单页。不同页可以有构图变化，但无叙事理由的新主色、字体体系或背景逻辑属于共享设计漂移。

## 交接

交接前用已收到的原始要求、所属 brief 与证据一次核对最终文案：必需内容是否实际出现、事实限定是否保真、引用是否对应原件。用户指定页位、原文或屏显内容不能移入讲稿或被封面减负删掉。修复有依据的遗漏和矛盾，只有定位不清时按需续读相应片段，不再通读附件或追加一轮 inspect 代替内容核对。

局部措辞、CSS 和普通排版自行解决；必需素材、事实边界、页职责或共享设计需要决定时，向 Orchestrator 说明页码、可见依据和所需决定。交接只写负责页、已完成范围、真实产物、当前像素结论和开放问题，不复制长篇制作过程。输入更新后只补受影响部分，不从头制作。
