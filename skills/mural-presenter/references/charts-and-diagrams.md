# 图表与图解决策

本文件用于数据、比较、流程、架构、机制、地图和复杂关系页。先决定页面要回答的问题，再选择图型和构图；不要从“哪个图看起来高级”开始。

## 目录

- 1. 问题到图型

## 1. 问题到图型

| 页面真正要回答的问题 | 优先表达 |
| --- | --- |
| 数值随时间怎样变化？ | 折线图、面积图；阶段很少时用斜率图 |
| 哪个类别更高或更低？ | 排序条形图、棒棒糖图 |
| 两个时点怎样改变？ | 哑铃图、斜率图 |
| 两个变量是否相关？ | 散点图；有第三变量时谨慎使用气泡 |
| 数值如何分布？ | 直方图、箱线图、小提琴图 |
| 总量由哪些部分组成？ | 100% 堆叠条形图；类别很少且稳定时可用环形图 |
| 起始值怎样被正负因素调和到终值？ | 瀑布图 |
| 多个对象在同一组维度上怎样比较？ | 对齐条形图、热力图、紧凑表；雷达只用于少量已归一维度 |
| 两个维度如何形成取舍？ | 象限、散点矩阵 |
| 数量如何跨阶段流动？ | 桑基图或加权流图；没有真实数量流动时不用 |
| 事情按什么顺序发生？ | 流程图、时间线、路线图 |
| 系统由哪些层与接口组成？ | 架构图、分层图 |
| 原因如何导致结果？ | 因果链、根因树、鱼骨图 |
| 对象之间是什么关系？ | 关系网络；关系不重要时改用分组或比较 |
| 地理位置与区域差异是什么？ | 地图、热场、点位、路径与局部放大 |

图型名称不是合同。最终计划还要写清类别、series、值、单位、时间范围、比较口径和页面结论。

## 2. 图表共同原则

- 一页只建立一个主要定量结论，标题直接写发现。
- 主图表获得与结论相称的画布；不要把图缩在大面板中的角落。
- 关键系列使用强调色，普通系列退为中性或同色阶。
- 优先直接标注关键值和对象，减少来回寻找图例。
- 坐标轴、零基线、排序和截断必须与论点一致；有意截断时明确说明。
- 单位、时间、样本、口径和来源进入对应讲稿；页面只保留听众必须看到的信息。
- 图表不是装饰背景。不能用生成图伪造数据，也不能让动画改变数据终态。

## 3. 常见定量图型

### 条形与棒棒糖

适合类别比较。类别名称较长时优先横向；按数值或叙事顺序排序。条长编码数值时保留零基线。只有关键对象使用强调色，其余保持稳定。

### 折线、面积与斜率

时间必须沿单一方向递增。系列较多时直接标注线尾，或拆成小多图。面积图只在累计量或总量感确有意义时使用。两个时点的变化优先用斜率图而不是折线。

### 散点、气泡与象限

写清横纵轴意义、单位和样本。象限线必须对应真实判断阈值，不用四象限装饰普通要点。气泡大小只有在第三变量准确且可比较时使用。

### 环形、堆叠与瀑布

环形图只用于少量、稳定且可辨认的部分，并在中心放总量或结论。跨周期比较构成优先 100% 堆叠条形图。瀑布图的起点、正负驱动和终点必须能数学调和。

### 分布图

直方图展示频数或密度，箱线图展示中位数、四分位和异常值。不要把均值柱状图冒充分布。样本少或分布不稳定时在讲稿说明边界。

### 雷达与热力图

雷达适合少量已归一化维度，不适合精确比较多个系列。对象或维度较多时使用热力图或对齐条形图，并保持色阶含义单调、可解释。

## 4. 表格、矩阵与地图

### 紧凑表格

- 使用有意义的列宽和数字对齐，不把表格缩成截图。
- 只高亮需要比较的行、列或单元格。
- 文本密集时先删冗余列、合并单位和改写列名，再考虑缩字。
- 论文表格优先忠实重排；无法保证映射时展示清晰裁图并在讲稿解释。

### 矩阵

矩阵的两个轴必须能命名，位置应来自真实判断。只有分组没有二维含义时，不要为了版式画四象限。

### 地图与空间图

地图必须保留对象身份、方位或真实空间关系。点位、路径、区域、热场和标签使用同一坐标系统。关键区域可局部放大，但全局位置仍需可追溯。

## 5. 流程、架构与机制图

### 顺序流程

节点包含动作和结果，连线明确方向。线性流程不要包装成循环；存在分支时写明判断条件与汇合位置。

### 时间线与路线图

时间线表达已经发生或明确安排的时间；路线图表达阶段、目标、依赖和里程碑。节点落在同一轴线上，标签从同一坐标系统定位。

### 架构与层级

先确定层、模块、接口和方向，再决定容器。层与层之间的关系比框的外观更重要；同一形状不要同时代表系统、数据和动作。

### 因果、根因与反馈

因果链使用有向连接。根因图让结果最醒目，原因族保持可读。反馈回路必须形成真实闭环，并区分正向、抑制或延迟关系。

### 领域机制图

科学、技术、医疗和工业页需要领域可辨认的对象或输出，例如样本、仪器、光谱、显微图、CT、界面、零件或检测结果。通用圆、矩形、六边形只能组织关系，不能替代领域证据。

大型关系图优先 Canvas 几何 + HTML 标签，或真实/生成无字底图 + HTML 标注。需要节点、连接、归组、判断和 callout 的具体视觉语法时，再读取 `shape-grammar.md`。

## 6. 页面构图

图表和图解页先选择一种主辅关系：

- **主图舞台**：图占主要安全区，标题、结论和少量注释贴近真实锚点；
- **证据—解释**：一侧是 Figure、图表或真实对象，另一侧只解释最重要的读法；
- **同尺度比较**：两个对象使用同一坐标、裁切或比较维度；
- **全局—局部**：先给整体，再放大关键区域；
- **路径—决策**：路径或机制贯穿页面，结论落在终点或关键分支；
- **数据海报**：一个数字或一条曲线成为视觉焦点，其他信息负责口径和意义。

主要图形通常应占据可用正文区的大部分视觉重量。不要在半屏槽位中再嵌套多栏图表，也不要为了保留空卡片把图形压缩成中央小岛。

## 7. 实现与证据完整性

- 定量图表使用本地 ECharts；最终 HTML 引用的 JS 必须真实存在。
- Canvas 只画几何，准确文字和数值用 HTML 标签；CSS 尺寸、内部尺寸、DPR 和标签坐标属于同一系统。
- SVG 只用于小图标、箭头、标记和用户提供的准确矢量资产。
- 图表数据保持 `类别 × series × 值` 的完整映射，不把不同列错当总分，也不把一维数组随意切成多个系列。
- 区分观测、估计、预测和情景；不可得数据改为定性构图，不展示假占位值。
- Figure 必须使用独立裁图或忠实重排；整页论文只有在“页面原貌”本身是证据时才上屏。

## 8. 像素检查

先看联系表判断页面焦点和图形尺度，再用全分辨率单页检查：

- 图表标题是否真的是结论；
- 类别、series、图例、标签和值是否一一对应；
- 节点、箭头、方向、图例和页面文案是否语义一致；
- 图形是否使用足够画布，而不是细小装饰；
- 标签是否达到投影字阶，没有被线、节点或页脚遮挡；
- 颜色是否保持数据和对象的原始含义；
- 论文 Figure、地图和专业输出是否清晰可辨。

如果视觉上只有通用几何和几个标签，无法看出领域对象、关系方向或页面结论，即使没有溢出也不算完成。
