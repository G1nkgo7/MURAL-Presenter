# 通用设计原则

本文件只讲跨风格的设计判断。风格词汇和用户点名的内置系统见 `style-routing.md`，具体构图见 `layout-patterns.md`。

按页面需要读取相关章节，不必从头通读。

## 1. 先判断场景与视觉量

设计由两个独立问题决定：

1. **语气多正式**：由听众和场合决定。政务、学术、法律、医疗和严肃评审更克制；品牌、文化、活动、故事和发布会可以更有表现力。
2. **内容需要多少视觉承载**：由内容决定。机制需要解释图，数据需要图表，人物和产品需要图片，封面和章节页需要主视觉。

克制只减少无意义装饰、字体数量和氛围堆叠，不减少有用的图片、图表和解释图。纯文字、细线框和大片空底不是“克制”，只是视觉信息不足。

每套 deck 先写一句视觉主张。它应能解释本任务的受众、内容和场合，而不是把参考模板换色。

## 2. 背景与色彩

### 2.1 建立背景系统

先确定一个内容页共同的基础画布，再定义少量有叙事用途的变化：

- 同色阶明暗变化；
- 定向渐变；
- 局部大色场；
- 有来源感的环境光；
- 低对比颗粒、网点、纸纹或主题纹样；
- 图片背景。

内容页可以更安静，峰值页和特殊页可以更强。变化必须继承同一色彩故事和图形语法。

学术、组会、合规和严肃评审可以使用冷白、冷灰或克制深色。品牌、招商、文旅、文化、课程导入和活动场景不应无理由整册铺同一纯色底。

### 2.2 颜色要有职责

- 主色建立世界，强调色只用于真正需要注意的结论、数据或节点。
- 类别、状态和风险使用稳定的颜色语义，不为了“更花”随意换色。
- 涨跌、风险和状态同时使用颜色与箭头、符号或文字，不只靠色相。
- 图表的普通系列使用中性灰或同色系浓淡，让关键系列成为最强强调。
- 所有页面颜色来自 `base.css` token。

避免没有主题依据的默认科技配色，例如深藏青 + 霓虹青、靛蓝紫渐变和到处出现的圆形 glow。环境光必须能解释光源或隐喻，并服务页面焦点。

### 2.3 对比度

- 正文与背景对比度至少 4.5:1。
- 大字和大号 UI 至少 3:1。
- 图片上的文字使用定向 scrim、贴合文字的小托板或轻描边，局部提高可读性，不把整张图片压黑。
- 暗底上的小字使用足够亮的颜色，不用深灰、暗金和低对比棕色。

`render.py` 的对比度结果用于定位，最终仍看像素。

## 3. 字体与排版

### 3.1 字体角色

- 中文标题和正文必须使用已登记、可随 deck 打包的中文字体。
- 正文、表格和图表标注使用稳定的正文无衬线或衬线字体。
- 展示体只承担标题、章节号和少量强调，不进入长正文。
- 等宽字体只用于代码、坐标、数据 ID 和确有技术含义的注释。
- 用户提供字体时优先使用；未覆盖字符由字体包回退。

先使用完成任务所需的最少字体角色；表达型场合可以增加展示或手写声部，但每种字体都必须有明确职责。具体字体路线按需读取 `fonts.md`。

### 3.2 字阶与换行

- display、标题、正文和辅助信息形成清楚层级。
- 正文、图表标签、Canvas 标签和图例不低于 `--fs-min`。
- 长标题降低字号或调整构图，不用负字距硬塞。
- 中文粗重大标题保持正常或略正字距。
- 一行能放下的短句不手动换行。
- 手动断行只在语义完整处，不留下 1–3 个孤字或孤立标点。
- 数字 + 单位、人名、地名、机构名和专有词组保持不拆行。

### 3.3 屏显文案

- 使用短句和可扫描结构，不把讲稿整段搬到页面。
- 中文内容使用中文标点，英文短语使用英文标点。
- 同一信息不在标题、副标题、角标、badge、callout 和页脚中重复。
- 来源和扩展说明进入讲稿或独立参考页。

## 4. 图片

### 4.1 什么时候使用图片

- 人物、地点、产品、作品、事件和真实案例优先使用真实图片。
- 氛围、故事、隐喻、虚构人物和未建成场景可以生成图片。
- 图片应承担识别、证据、场景或情绪中的至少一种作用。
- Logo、小图标、装饰纹理和微型缩略图不算主要图片。

不为数量加入无关图片，但也不要因为 CSS 更可控而放弃本来能显著提升理解的图像。

### 4.2 图片怎样进入版面

- 一张有分量的主图通常优于许多散点小图。
- 根据内容选择满幅、图文分屏、局部裁切、画框场景或透明主体。
- 保持原始比例，不拉伸、不压扁。
- 裁切先保护人脸、头顶、手势、完整产品、Logo、作品主体、坐标轴和图例。
- `subject-only` 使用真实 Alpha 抠图；带白底或奶油底的 RGB 矩形不能偶然贴到异色画布上。
- 人物、动物、植物、艺术品、食物、热成像、光谱、显微和遥感图中的颜色具有识别或证据意义时，应保留。

### 4.3 图上文字

文字可以压在照片、插画和 Canvas 上，但必须明确处理可读性：

- Canvas 主要画几何，准确文字放 HTML 层；
- 使用定向 scrim、局部托板或浅描边；
- scrim 从画布边缘渐退，不使用有明显边界的黑色矩形；
- 装饰层 z-index 低于文字。

## 5. 数据图表

页面需要选择图型、数据构图或复杂图解时，完整读取 `charts-and-diagrams.md`；本节只保留共同底线。

- 使用 ECharts，不用生成图伪造数据图表。
- 一张图只强调一个主要结论。
- 数据、单位、时间范围、来源和比较口径齐全。
- 类别、series、图例、标签和值一一对应。
- 不使用 3D、过度动效和装饰性渐变掩盖数据。
- 类别名较长时调整轴向、换行或图型，不靠缩小标签解决。
- 关键结论可以直接标在图中，其他说明放讲稿。

## 6. 流程、架构与机制图

优先使用 Canvas 几何 + HTML 文字，或无文字图片 + HTML 标注。

页面需要范围、实体、判断、方向、层级、归组或 callout 时，按需读取 `shape-grammar.md`，先确定关系，再选择形状和实现媒介。

规划时写清：

- 对象；
- 关系；
- 方向；
- 层级；
- 视觉编码；
- 听众最终应读出的结论。

线段、弧线和虚线表达流向、因果、反馈或先后时，必须有箭头或等价编码。图例、标签和方向不能互相矛盾。

科学、技术、医疗和工业页优先展示领域可辨认的输出，如光谱、显微图、CT、检测界面或样本—仪器—结果链。通用几何只能表达抽象关系，不能冒充领域证据。

SVG 只用于小图标、Logo、箭头、标记和小型装饰。除非用户明确要求矢量交付，不把手写 SVG 当半屏或全屏主视觉。

## 7. 布局与空间

### 7.1 对齐和间距

- 全册使用稳定安全边距和列栅格。
- 同级元素共享左线、基线或中线。
- 数字列右对齐或小数点对齐。
- 间距使用少量固定档，组内紧、组间松。
- 同组单元使用相同内部结构。
- 装饰按边缘、栅格或成组关系组织，不散撒。

### 7.2 使用画布

- 常规内容页的主体在安全区内形成稳定重心。
- 主表、矩阵、时间轴和流程图默认横向使用可用宽度。
- 内容多时重组结构或拆页，不缩字和隐藏溢出。
- 内容少时缩小容器、放大主视觉或合并页面，不让短内容钉在高大卡片上沿。
- 短卡确需等高时，内容组垂直居中，并保持文字左对齐。
- 每块留白都能解释为聚焦、节奏、方向或换场；说不出用途的单边死白需要重排。

### 7.3 页面高度

- `.slide-body` 只有一个高度所有者。由 `top + bottom` 定高时不再写固定 height；由 `flex:1` 占满时不叠加 `height:100%`。
- 页面专属满高布局放在内部 stage，并给 grid/flex 子项 `min-height:0`。
- 不用固定像素高度、`margin-top:auto` 和 `overflow:hidden` 掩盖几何问题。
- 页脚是保留区，正文和图片不得无意侵入。

## 8. 跨页节奏

为每页选择：

- `anchor`：章节起始或关键命题；
- `dense`：信息密集；
- `breathing`：低密度、单焦点。

角色服从叙事，不机械轮换。相邻页应改变构图方向、媒介、图片占比或信息密度中的至少一项，但不为追求多样而破坏整册语言。

封面、章节页和结尾页共享字体、颜色语义、图片处理和图形语法；它们不必复制同一几何。

## 9. 避免模板感

避免：

- 默认靛蓝紫、通用科技 glow 和无主题渐变；
- emoji 代替图标；
- 圆角卡 + 左彩条的通用 dashboard 组件；
- 卡套卡、玻璃拟态和满屏平均用力；
- 无意义的技术注、坐标、档案号、场记和英文标签；
- 所有页面都使用“眉签 + 大标题 + 一排等权卡片”；
- 同一母题在多数页面重复粘贴；
- 编造数字、占位文案和未完成状态上屏；
- 为了显得“高级”而默认黑金、米白、深蓝或灰阶图片。

好的页面通常由准确比例、清楚层级、稳定重心、有语义的用色、有判断的裁切和一个明确设计动作组成。复杂细节集中在局部，其余区域保持安静。

## 10. 技术交付门

- 正文对比度 ≥ 4.5:1；大字 ≥ 3:1。
- 听众需要阅读的文字不低于 `--fs-min`。
- 无裁切、溢出、破图、真实遮挡和页脚覆盖。
- 图片保持比例，主体保护区域完整。
- 页面修改后重新渲染并查看新像素。
- 机检与像素冲突时，以像素和 DOM 为准，记录 `checker mismatch`，不为清告警破坏页面。
