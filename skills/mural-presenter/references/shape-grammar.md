# 图形与形状语法

本文件在页面需要流程、层级、关系、标注、结构化装饰或明确的几何视觉语言时读取。它把常见形状转译为 HTML/CSS/Canvas 的语义工具，不是要求把所有形状都用一遍，也不是 OOXML 形状枚举。

## 1. 先判断关系，再选择形状

| 要表达的关系 | 首选语法 | 不应替代的内容 |
| --- | --- | --- |
| 范围、模块、证据区 | 矩形、圆角矩形、框线或色场 | 不用等高空卡片填满页面 |
| 实体、节点、状态 | 圆、椭圆、圆点或具名图像 | 真实人物、产品和样本优先用图像 |
| 判断、分支、阈值 | 菱形或清楚的分叉节点 | 普通步骤不必全部画成菱形 |
| 阶段、推进、因果 | 有方向的线、箭头、带标签路径 | 无箭头的装饰线不能冒充流程 |
| 层级、优先级 | 嵌套框、阶梯、金字塔或同轴层 | 长段文字不要挤进三角形 |
| 循环、反馈 | 环线、弧线和清楚的回流箭头 | 只有四步列表时不必强画圆环 |
| 归组、包含 | 大括号、方括号、框选或背景带 | 同组关系不能只靠相近位置猜测 |
| 注释、引用、局部放大 | callout、leader line、局部框和图窗 | 标注线必须落在真实对象边界 |
| 比较、权衡 | 平行轨道、统一基线、天平或连续轴 | 两方案必须使用同一比较维度 |
| 强调、庆典、冲击 | 星形、爆炸形、丝带或放射线 | 仅限语义匹配的促销/节庆/海报页 |

流程图的开始/结束、过程、判断、文档、数据和人工操作等标准形状可以使用，但只有在听众熟悉该符号，且符号能减少解释成本时才采用；否则用更直接的节点标签。

## 2. 每册先定义一个形状系统

在 `plan/design-brief.md` 中定义：

```text
shape_grammar:
  primitives: <本册主要使用的几类基础形状>
  corner_policy: <直角、微圆角、大圆角或混合规则>
  stroke_hierarchy: <主路径、辅助线和边界的粗细关系>
  connector_grammar: <方向、箭头、标签和锚点规则>
  callout_grammar: <注释框、引线和局部放大规则>
  decorative_shapes: <允许出现的装饰形状及使用场景>
  avoid: <容易产生误解或模板感的形状习惯>
```

选择少量具有共同特征的形状即可。设计亲缘性来自一致的圆角、线宽、端点、填充和标签方式，不来自每页重复同一个图案。

## 3. 基础形状的设计角色

### 几何基元

- **矩形 / 圆角矩形**：模块、证据区、图片框、文本托板；内部短内容较少时让内容组垂直居中，不把卡片做得又高又空。
- **圆 / 椭圆**：实体、状态、循环节点、聚焦光斑；文字较长时把标签放在圆外，不强塞进节点。
- **三角 / 菱形**：方向、判断、警示和尖锐张力；不用作普通信息卡背景。
- **六边形**：网络、材料、蜂窝或工程模块；主题没有此类语义时不要因为“科技感”滥用。
- **弧、圆环、扇区**：循环、范围、进度和比例；有精确数据时交给 ECharts，不手画伪比例。
- **框、相框、图窗**：局部聚焦、作品/证据展示和画中画；框本身不能比被展示对象更抢眼。

### 方向与连接

- 线条从源对象边界出发，到目标边界结束；不要穿过标签或停在空中。
- 流向、因果、反馈和迁移必须使用箭头、递进宽度、编号或其他明确方向编码。
- 连接线含义不明显时，在路径旁写动词或关系标签，如“输入、转化、反馈、约束”。
- 主路径比辅助关系更粗或更亮；高亮只落在一个真正重要的关系上。
- 不删除承担语义的线、箭头和图例来解决 bbox 告警；先用最终像素判断是否真的冲突。

### 归组与注释

- 大括号、方括号和背景带适合表达归组；不要用无语义装饰框包住所有内容。
- callout 由对象、引线、短标签组成；引线必须准确指向对象，不与正文混为一条装饰线。
- 需要解释图像细节时优先使用局部放大图窗，而不是把整张主图缩小给旁边文字让路。

### 展示性形状

- 星形、爆炸形、丝带、卷轴、波形和自由形状适用于海报、活动、儿童、文化或品牌场景；在严肃汇报、学术和技术页中应克制。
- 手绘线、涂鸦、纸片和不规则轮廓要与图片、字体和场景共同成立，不能单独出现成随机装饰。
- 数学符号、括号和运算符只有在它们真的表达计算或逻辑时使用。

## 4. 选择实现媒介

| 任务 | 默认实现 |
| --- | --- |
| 平面容器、色场、分隔、简单箭头 | HTML/CSS |
| 必须精确表达节点、方向、层级或反馈的关系 | Canvas 几何 + HTML 标签 |
| 定量趋势、比例、分布和雷达 | ECharts |
| 真实人物、产品、场景、作品和实验输出 | 真实图片或忠实裁图 |
| 小型图标、Logo、箭头和局部标记 | 小型 SVG |
| 氛围、故事画面、过程切面、空间隐喻和概念场景 | 生成图或真实图 + HTML 标注 |

先问“这个内容能否由一个具体画面讲清”。能时优先使用真实图或无文字生成图，再用 HTML 添加准确说明；不能时才进入结构化图解。大型关系图不使用一张带 AI 文字的生成图替代准确结构。Canvas 只画必要几何，准确文字和数字用 HTML 标签；所有层使用同一坐标系统。大型 SVG 不属于主视觉路线。

## 5. 页面验收

- 观众能说出形状和连接表达的对象、方向与关系；
- 图形占据与其信息职责相称的空间，不缩在右下角；
- 图例、颜色和形状语义一致，没有标题说 A→B、图例却写 B→A；
- 领域方法页有真实对象或忠实输出，不是“圆形 + 矩形 + 横线”的装饰占位；
- 标签达到投影字阶，连接线和箭头在联系表尺度仍可辨；
- 形状系统与本册字体、颜色、图片和圆角语言一致。

形状是表达关系的工具。若删掉形状后信息没有任何损失，它很可能只是装饰；若删掉后关系消失，它就必须被准确保护。
