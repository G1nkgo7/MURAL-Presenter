# 产品发布与技术工程

## 听众任务

让听众识别产品或系统，理解它解决什么、如何工作、为什么可信、有哪些边界，以及怎样落地。

## 叙事骨架

真实问题 → 产品或系统主张 → 使用体验 → 架构/机制 → 性能与证据 → 约束/安全 → 路线与行动。

## 证据对象

- 产品图、界面、部署现场和真实使用场景；
- 输入、处理、输出和反馈关系；
- 模块、接口、依赖、数据流和控制流；
- 指标、基线、测试条件和失败边界；
- 路线图、集成方式和运行约束。

## 常用页面家族

| 页面职责 | 适合的表达 |
| --- | --- |
| 产品识别 | 大幅产品/界面/现场 + 核心主张 |
| 工作原理 | 有方向的机制图和领域对象 |
| 系统架构 | 层级、模块、接口和数据流 |
| 性能证据 | 一图一结论的测试或基准 |
| 部署与边界 | 环境、依赖、安全和回退路径 |

## 视觉与节奏

关系决定图形：模块用容器，数据流用箭头，状态用明确编码，界面与产品用真实图。技术感来自精确结构和材料，不来自 HUD 边框、伪坐标和无意义霓虹。

## 容易退化的方向

- 通用深蓝背景覆盖所有技术主题；
- 连接线没有方向，或线条只是装饰；
- 产品缩在角落，页面主体是泛化文字；
- 未说明测试口径就强调百分比和提升值。

## 规划交接

逐页计划写清节点、关系、方向、接口、状态和证据。若页面需要几何关系图，路由到 `shape-grammar.md`；若需要空间、产品或人物识别，优先准备真实图片。
