# 风格路由

本文件是视觉路线索引，不是模板全集。先由场景分类确定听众任务、证据和页面家族，再从这里选择一个风格群组取得设计词汇。自主设计时不要自动套用成套系统；只有用户明确点名内置系统时，才读取对应的系统文件。

## 渐进阅读顺序

1. 读本页，选择一个主风格群组；
2. 自主设计：只读取该群组链接的一份 `style-families/*.md`，从中选择一个主家族；
3. 用户点名内置系统：只读取目录中包含该系统的一个文件；
4. 在 `plan/design-brief.md` 写成适合本任务的视觉导演方案；
5. 后续 Slide Group 消费设计合同，不重新浏览风格库。

不得为了比较而通读全部风格簇或系统，也不得把两个成套系统拼接。用户给出的完整设计系统、模板或风格参考优先于本索引。

## 可执行视觉系统的结构

无论原创还是指定系统，最终都要回答：

```text
visual_thesis: <一句能指导取舍的视觉主张>
signature_visual: <最能被辨认、但不会机械重复的视觉动作>
category_baseline: <场景对可读性、证据和节奏的要求>
canvas_and_grid: <基础画布、栅格、安全区和允许的状态变化>
palette_roles: <背景、正文、线、强调、状态色的职责>
typography_roles: <标题、正文、数字、标签和点缀字体>
image_treatment: <真实/生成图的裁切、色调、边缘和文字安全区>
chart_language: <坐标、系列、标签和强调方式>
shape_grammar: <基元、圆角、线宽、连接和注释语法>
special_page_system: <封面、章节页、结尾页的亲缘与不同动作>
page_families: <本册会使用的主要页面家族>
density_rhythm: <聚焦、解释、证据和呼吸如何交替>
fallback: <招牌素材不可得时怎样保住系统>
avoid: <本任务最容易出现的退化>
```

风格不是颜色名称。只有颜色、字体、图片、形状、构图和节奏形成同一判断时，才算完成视觉系统。

## 轻量导演试镜

用户已经给出完整可执行方向时，直接验证并采用；自主设计且方向仍含糊时，在落盘前快速比较少量真正不同的候选。候选必须在招牌视觉、图片处理、特殊页动作或内容页媒介节奏上有实质差异，不是只换颜色。

只问：

- 哪个更像当前题材，而不是换标题也能复用的通用报告？
- 哪个能把现有图片、数据、对象或材料放大成构图？
- 哪个在缩略图尺度仍有明确开场、峰值、章节阈值和终幕？
- 哪个能由当前素材和工具诚实实现，并有成立的 fallback？

选择后只把胜出的方向写入 `plan/design-brief.md`。把页面地图当作尚未渲染的联系表，连续出现同一分屏、卡片、矩阵、中央小岛或同底色时，先调整媒介、主辅尺度和视觉节拍，再进入逐页计划。

## 色彩路线

先确定色彩职责，再选具体色值：

- **明暗**：浅色纸感、深色沉浸、高对比或柔和中性；
- **温度**：冷静、温暖、大地、冰川或暮色过渡；
- **饱和度**：低饱和、自然色、高能撞色或局部荧光；
- **结构**：单色明度、主辅双色、分类色板或有叙事用途的渐变；
- **状态**：成功、风险、当前、历史和对照色必须具有稳定语义。

不要按“科技=蓝、环保=绿、女性=粉”机械映射。主题对象、用户指定、真实素材和场景共同决定色彩。

## 选择检查

- 它是否服务听众任务和证据，而非只满足风格名？
- 它是否已经明确主辅比例、图片行为、数字声部和特殊页动作，而非停留在形容词？
- 招牌动作是否有真实素材和实现条件？没有时 fallback 是否仍然成立？
- 字体、图片、颜色和形状是否共同表达同一气质？
- 特殊页与内容页是否属于同一世界，又有节奏变化？
- 视觉状态变化是否有进入和退出承接，而非突然换一套 Deck？

选定后把本次实际方案写入 `plan/design-brief.md`，不要只写“科技风、杂志风、黑金”等标签。
