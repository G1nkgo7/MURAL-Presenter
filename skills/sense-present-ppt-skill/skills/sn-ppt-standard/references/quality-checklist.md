# 质量检查清单(单页 + 整套)

幻灯片质量的**统一判据**,两级:

- **单页检查** —— 一页能否清楚表达、稳定专业。**slide subagent 自检** 与 **review subagent 逐页复核** 都用这套。
- **整套检查** —— 整份能否围绕目标顺畅讲完、多页风格统一。**review subagent 横扫全套** 用这套。

通用优先级:**先硬后软**——能直接毁掉一页的「硬伤」(见单页·维度3)必须先清零,再谈层级 / 美感这类「软伤」。

---

## 一、单页检查

一页要同时立得住:**内容讲得清 + 视觉撑得住**。

### 1. 表达与内容逻辑
- 主题 / 重点 / 结论清楚;**标题与正文指向同一表达目标**(不跑题、不各说各的)。
- 论证信息**支撑页面主旨**(数据 / 论据服务于这页要说的那一件事)。
- **完成当前页型任务 + 必含要素**(案例页有具体案例、介绍类有代表作品、数据页有真实 / 标注数据、方案页有具体做法……见 SKILL.md 页型词表后的清单)。〔页型名按 deck 语言可能是中文或英文 role(结束页=Closing、案例页=Case Study 等),按**页型语义**认,别因字面语言不同而漏判。〕
- **文本与规划一致**:上屏文字就是规划里的文案(未被改写 / 扩写 / 编造);**无规划外内容**(自创页眉 / 水印 / 「机密·内部使用」标识 / 日期 / 多余装饰文字;但 base.css 自带的 `.slide-footer` + `.page-no` 不算自创)。
- 内容本身无逻辑问题(因果 / 顺序 / 归类不自相矛盾)。**事实准确性**:每条上屏事实能追溯到用户材料、`info_pack.json` 或前置 Research 主报告，或已标"示意 / 待核";涉及具体人 / 作品无明显错误(性别 / 称谓 / 归属)。Static 出口不得为修复缺口自行搜索；编排器抄写时必须回已有来源逐项核对。

### 2. 版式组织与阅读路径
- 有**明确视觉中心**,主次层级清楚(一眼知道先看哪)。
- 排版稳定美观(对齐、网格、留白均衡,不挤不空)。
- **观看顺序顺畅**(视线自然流动,不跳来跳去)。
- 装饰**不干扰阅读**(纹理 / 形状 / 图标是辅助,不抢内容)。

### 3. 可读性与技术完成度
- 关键信息清楚可读(字号够大、对比够、不被压盖)。
- **最小字号 ≥ `--fs-min`**(投影场景可读);没有为塞内容把字缩到看不清。
- 表达元素**完整呈现**,能读出主要含义(图表有轴 / 图例 / 标签,不是半截)。
- 导出质量清晰稳定(不糊、不截半截)。
- 画面无缺陷。

> **本维度的「硬伤」——必须先清零(slide subagent 自检红线):**
> ① 溢出 / 出血(**内容**——文字 / 图表 / 卡片——越过 1600×900 或容器边)。注意:`.slide` 是 `overflow:hidden`,溢出会被**静默裁掉**而非露白条黑条,所以要**主动核对**页脚 / 页码 / 正文首末行 / 图表轴标签是否完整,别等"看到出血"。〔满铺背景图用 `.slide--bleed` 是合规的,不算出血。〕
> ② 遮挡(文字 / 图表 / 图片 / 形状互相压盖);
> ③ 占位残留(空框、占位文字、缺轴 / 图例 / 标签的半截图表);
> ④ 破图破表(`<img>` 或 ECharts 没真正渲染出来);
> ⑤ 中文豆腐块(□□□,字体没加载);
> ⑥ 可读性不足(文字对比太低看不清);
> ⑦ 配色出界(调色板外的红 / 粉 / 绿、ECharts 默认色、多系列没用 `--series-*` token、涨跌只靠色相而无 ↑↓/正负号、或涨色 = 警示色)——一律换回 base.css 的 token + 双通道。
> ⑧ 图片机会状态或消费错误：图片机会页缺合规 `source_hint:` / `image_status:`、残留 `planned`；`ready` 没有
> authentic / generated illustrative 来源类别、合规 `image_source:` 或真实本地路径，最终 HTML
> 没有引用本地图片、误把 source 当远程图片引用，或改用 SVG / CSS 替代；`unavailable` 没有
> native/bundled 的
> 具体失败原因或仍伪造路径。只有规范记录 `unavailable` 后才允许无图回退。
> ⑨ 真实性错误：人物、真实产品、地点、作品、案例、历史现场、行业 / 生活实景或真实产品 UI /
> 界面截图在搜索失败后改用生成仿真素材，或生成的示意 / 艺术重构 / 概念化画面被当成真实证据。

### 4. 视觉元素与风格适配
- 各元素**协调**(配色 / 字体 / 图形语言一致)。
- 元素间有清楚层次,**视觉服务内容重点**(强调的是关键信息,不是装饰)。
- 视觉风格**贴合 deck 选定的 风格 / 色调 / 主色**(见 base.css 与 plan/deck.md)。
- **素材用得准**:无多余素材(每张图都承载内容);未被严重裁切毁主体、未拉伸变形、比例匹配槽位(对不上用 `contain` 而非大裁)。
- **图片真实性正确**：人物、真实产品、地点、作品、案例、历史现场、行业 / 生活场景，以及真实
  产品 UI / 界面截图，按“可用且相关用户素材 → native search → bundled search → none”取得；
  搜图失败进入 `unavailable`，没有生成仿真替代。生成图片只用于规划明确的示意 / 艺术重构 /
  概念化表达，且没有冒充真实证据。封面 / 章节转折只是默认图片机会，已根据主体分流，没有
  被一律判成真实图片。
- **图片来源可审计**：每个 `ready` 都有 `image_source:`。`authentic search` 是去除凭据、鉴权和
  签名 query 的来源页面 URL（必要时带 referrer 语义），不是只有 CDN / 图片直链；无法安全保留
  完整 URL 时只写 `来源域名 + redacted`。`authentic user_material` 使用
  `info_pack.user_assets.reference_images[<n>]` 或
  `raw_documents.documents[<doc_index>].inherited_images[<image_index>]` 稳定定位符，已有 deck 素材
  使用 `deck_asset:assets/<filename>`；`generated illustrative` 是 `generated — native <tool>` 或
  `generated — bundled <tool>`。这些字段不得含用户原始绝对路径、token、密钥或其他 secret；
  HTML 只引用本地 `image:`，不消费 `image_source:`。
- **起始来源提示完整**：每个图片机会都有一行 `source_hint:`。真实图片只能是
  `info_pack.user_assets.reference_images[<n>]`、
  `raw_documents.documents[<doc_index>].inherited_images[<image_index>]`、
  `deck_asset:assets/<filename>` 或 `search — no relevant user material`；生成图片只能是 `generate`。
  提示证明规划器已检查 `info_pack` 中的用户上传图片、文档继承图片和已有本地素材；它只决定
  起始路由，最终采用来源仍以 `image_source:` 为准。
- **UI 分类正确**：真实产品 UI / 真实界面截图按真实图片核对来源与本地路径；示意 UI / 界面
  结构 / 组件关系使用 HTML / CSS / SVG 代码表达。图表、流程、架构、关系和图标同样保持代码
  表达，没有用图片伪造可编辑结构，也没有用代码仿造真实产品截图。
- **图片与背景协调**：除封面和明确章节满图页外，图片位于前景内容槽，裁切保留主体，必要时
  只加局部蒙版 / scrim 保证文字可读；没有替换、压死或擅自改写 `base.css` 的统一背景。
- 无低质效果(廉价渐变 / 滥用阴影毛玻璃 / 千篇一律的 AI 味套版)。
- **层级自信**:标题明显大过正文(标题 ≥ ~2.1× 正文、小标题 ≥ ~1.45× 正文),密页上标题 / 正文 / 标签**不挤成一个字号档**;一眼能分出先看哪。
- **强调克制**:accent 只点**一处**关键(≤ 约 10% 着墨),不是标题线 / 眉签 / 要点 / 数字全染 accent;正文 / 分隔线 / 标签用中性墨色浓淡。
- **不是 AI 默认色**:没有"深藏青 + 霓虹青/电光蓝"那套默认科技色、没有 `#6366f1` 靛蓝;暗底有色温,accent 不刺眼(降饱和)。
- **面板有体积**:卡片 / 面板靠色调分层(页底→面板→内元素三级),不是扁平深色盒子;没有标题后那团泛用径向"光晕"假景深。
- **对齐**:同一页文字块**对齐到同一条网格线**,没有"居中块 + 左对齐块"两套对齐混用;长标题 / 长句的折行不是忽长忽短的烂 rag。
- **数字 + 单位**:大数字的单位(亿 / % / 美元 / ×)是**小一号、退一步**(≈0.5× 数字、不抢戏),不是和数字一样大顶在一起;同一指标族单位 / 精度 / 千分位写法一致。
- **一排卡片对齐**:同一行的卡片**等高、内部各行(数字/标题/正文/脚注)落在同一条基线**,不是有的卡片矮一截、脚注高低参差。

## 二、整套检查

全套要能**围绕目标顺畅讲完**,且**多页之间风格统一**。

### 1. 目标场景
- 适配**汇报场景 / 展示对象**(受众、媒介、正式度都对得上)。

### 2. 全篇结构与跨页推进
- 整体结构**清晰、完整、有效**(封面 → 铺垫 → 论证 → 总结 / 行动 → **结束页 / Closing(封底,必有)**,叙事弧线完整)。
- 相邻页**自然承接**(不断层、不重复、不突兀跳跃)。
- **长 deck(≥8 页)分了"幕"**:有 2–4 个章节、**每幕前有过渡页**(不是一长串等权内容页平铺);封面列的目录板块都成了过渡页、顺序一致。
- **是"搭建"不是"清单"**:有一个统领论点、每页回扣它(不是每页换个指标重说"很大");没有两页讲同一宏观点没合并。
- **密度有节奏**:没有满密页背靠背、也没有极简页背靠背;任一页信息点 ≤3。

### 3. 视觉系统一致性
- 页面元素**多页之间保持统一**(配色 / 字体 / 页眉页脚 / 页码 / 间距同一套 token)。
- **固定框架全套一致**:标题位置 / 页脚 / 页码 / 安全边距套同一 base.css 骨架,没有逐页漂移(标题忽大忽小、装饰线乱动、重心忽上忽下)。
- **素材视觉配方统一**(同媒介 + 同调色 / 处理,不风格色调乱飞)。
- **图片机会逐页可审计**：逐页读取计划，确认每页都有 `visual_anchor:`，每个图片机会都有合规
  `source_hint:`。真实图片 / 生成图片
  机会页必须是 `image_status: ready — <authentic user_material | authentic search | generated
  illustrative>` + 存在的本地路径 + 合规 `image_source:`，或
  `image_status: unavailable — <native/bundled 的具体失败原因>` + 无图回退；`planned`、缺状态、
  空泛原因均不通过。`ready` 再对照 HTML 确认实际引用，不只凭截图猜；`unavailable` 对照页面
  确认没有仿真替代。
- **全册仍做漏判复判**：完成逐页账本后，再看纯文字、卡片、结构图或抽象 SVG 连续页，以及
  任何单页中的具体视觉对象，重新判断是否遗漏图片机会；连续页只是辅助信号，不是唯一触发。
  数据、流程、架构、关系、图标和示意 UI / 界面结构 / 组件关系确实主导时继续保持代码表达；
  真实产品 UI / 界面截图仍归真实图片。
- **不以数量验收图片**：不设置固定张数、页数比例或“每 N 页一张”；检查的是有内容价值的
  图片机会是否被识别，以及已落盘合格图片是否全部被页面实际消费。
- **同类页型有稳定表达**(所有数据页一个调性、所有对比页一个结构)。
- 页间**视觉复杂度 / 信息密度 / 设计精度相对均衡**(不忽繁忽简、忽精忽糙)。
- 无个别页明显低质拖后腿。

### 4. 整套美学气质 + 美术指导(治"模板味")
- 全套形成**一致的视觉气质**(像一个人做的一整套,不是拼盘)。
- 视觉语言**匹配主题与媒介**。
- **有设计概念,不是模板填空**:这套 deck 看得出一个**贴主题的设计概念 / 色彩故事**(写在 `plan/deck.md`),不是"换个色的通用 AI deck"。
- **版式不单调**:**不是每页都"眉签→大标题→一排卡片"**——等权卡片/宫格全套 ≤2 页、2×2 田字格 ≤1 次,其余页用了不同版式族;相邻页不雷同。
- **有破格 hero 页**:全套至少 1 页在叙事高点**打破栅格**(特大数字/词、满幅金句、或 >70% 主图/图表),和其它页明显不同。
- **母题贯穿**:封面的视觉母题在 ≥3 个内页以变体复现,不是封面用一次就丢。
- **图表是新闻图**:数据页标题写**结论**(发现句)不写题目;图直接标值、砍冗余轴/图例;KPI 一排里只有一个当头条。

### 5. 整体展示风险
- 没有**大量页面反复出现同类问题**(同一毛病系统性复发 → 多半是 base.css / 规划层的根因,应改设计系统而非逐页修)。
- 无**缺页 / 重复页 / 顺序错误 / 章节标题与内容不匹配**。
- **最后一页忠实遵循 `outline.md` 的既定页型和内容**，不得擅自补结束页。只有 outline 明确规划为「结束页 / Closing」时，才要求封底式收束、与前一页版式明显不同，且不含"感谢聆听 / 感谢阅读 / 感谢观看 / Thank you for listening / watching / reading"之类套话。

## 怎么用(各角色对照)

- **slide subagent**(`subagents/slide.md`):写完渲染后按「单页检查」自检,**硬伤优先清零**，修正轮次服从当前 Draft / Standard / Deep 档位。它看不到兄弟页,不负责跨页一致性。
- **review subagent**(`subagents/review.md`):先逐页读取 `plan/slide_NN.md`、对应 HTML 和可用的
  `assets/` 路径，核对 `visual_anchor` / `source_hint` / `image_status` / `image_source` / 本地图片实际引用，并确认
  source 类型与 ready 类别一致、HTML 没把 source 当图片消费，再结合截图过「单页检查」和「整套
  检查」。不得只凭截图猜图片机会、真实性或消费状态。
- **编排器**:规划期就用「单页检查·表达与内容逻辑」「整套检查·全篇结构」自检叙事与内容(规划期堵掉比渲染后返工便宜);复审清单回来后,按「整套检查·整体展示风险」判断是**改 base.css**(系统性根因)还是**重委派个别页**(局部问题)。
